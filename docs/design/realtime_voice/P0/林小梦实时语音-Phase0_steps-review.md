## 🔍 二、逐 STEP 问题标注

#### STEP-001 Phase0 命名空间脚手架与本地测试配置

**[冲突] · 严重程度：高**

> PLAN 原文：独立命名空间，不挂载正式用户入口；实验可删。  
> 步骤文档写法：在 `main.py` 挂载 `/api/phase0/realtime-voice`。  
> 问题说明：与用户已确认 **Q1=B（独立进程/入口，不改正式 `main.py` 默认挂载）** 冲突；同进程挂载增加误暴露与删除成本，也弱化「语音炸不影响文字」方向。  
> 建议：改为独立入口，例如 `python -m backend.phase0_realtime_voice.app`（或等价 `__main__`）；正式 `main.py` **默认不** `include_router`；测试页只连 Phase0 端口。文档中删除「必须改 main.py」任务。

**[幻觉] · 严重程度：低**

> 步骤文档写法：包路径 `backend/phase0_realtime_voice/`、前缀 `/api/phase0/realtime-voice`。  
> 问题说明：PLAN 未写死路径，已标 `[自定义]`，可接受。  
> 建议：保留，并在文首「已确认约束」中写明独立进程。

#### STEP-006 Phase0 只读人格/关系/对话查询

**[代码事实错误] · [不清晰] · 严重程度：高**

> PLAN 原文：读取「当前实际生效的人格配置」。  
> 步骤文档写法：参考并复制 `admin_config_service.get_active_config` 语义。  
> 代码实际情况：文字主链热路径在 `chat.py` 读 Redis `active_config:persona`（`REDIS_KEY_PERSONA`，定义于 `prompt_builder.py`），未命中则用 `DEFAULT_PERSONA`；`admin_config_service.get_active_config` 在缓存未命中时会 **写回 Redis**。  
> 问题说明：若 Phase0 import 并调用 `get_active_config(use_cache=True)`，既违反 Q2=A（碰 service），也可能在实验中写 Redis，与 PLAN「不向 Redis 写入测试…」精神冲突。  
> 建议（对齐 Q2=A）：在 Phase0 内实现只读加载——优先 `GET` Redis `active_config:persona`（不 SET）；未命中则直接查 `AdminConfig`（`is_active=True, is_draft=False, config_key` 与现网一致，一般为 `persona`），**禁止**调用 `admin_config_service`；禁止写 Redis。快照 SHA-256 基于最终采用的正文。

**[代码事实错误] · [不清晰] · 严重程度：中**

> 步骤文档写法：`addressing` / 称呼字段「待查契约文档」。  
> 代码实际情况：`Relationship` 含 `level`、`user_real_name`、`user_hobby_name` 等，无名为 `addressing` 的列；契约见 `docs/contract/current/relationship/data.md`。  
> 建议：字段表改为 `level` + `user_real_name` / `user_hobby_name`（小包「关系阶段与称呼」映射写死），去掉模糊 `addressing`。

**[遗漏] · 严重程度：低**

> 完成标志未写「未 import `admin_config_service` / `prompt_builder` 业务函数（常量复制除外）」。  
> 建议：完成标志显式禁止 import 上述 service；允许复制常量字符串 key 名到 Phase0 包内。
