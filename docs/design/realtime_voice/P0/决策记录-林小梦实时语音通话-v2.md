# 林小梦实时语音通话 PRD

> 版本：v2.0
> 状态：待评审
> 涉及模块：VOICE001（通话核心）/ VOICE002（语音记忆）/ VOICE003（通话内容安全）
> 不涉及模块（明确不动）：LIFE000-005、PER003、AGE003、现有 Doubao 文字对话链路、persona 配置结构本身

---

# 1. 功能背景

## 当前功能是什么
首页已有"语音通话"入口，但点击仅弹出"敬请期待"占位提示（`frontend/pages/index.html`），无实际通话能力。现有安全机制仅为 Redis 关键词扫描且异常放行（`content_safety_service.py`），无危机内容识别与响应能力。

## 当前存在的问题
- 无实时语音通话能力，产品定位与"陪伴感"存在体验缺口
- 内容安全机制未覆盖危机内容（自伤/自杀倾向）识别与用户侧响应
- 人设口径存在历史不一致（代码兜底/历史测试实录/PRD参考文案三个版本不同），需独立核实，不阻塞本功能开发

## 改造目标
新增一条完全独立的语音通话业务线：通话能力 + 通话后记忆炼制 + 通话内容安全响应，不改动现有文字对话链路、记忆链路（Step6）、安全模块的既有代码路径。

| C22 | 通话中网络异常 | 与静音判定（C8）分开处理：网络异常先给一个重连宽限窗口，重连失败才计为通话结束；不与"检测不到有效语音"的静音逻辑合并 |

| C24 | 危机检测实现方式 | 维持纯关键词匹配（`crisis_keywords`），不叠加语义/LLM判断层；接受"隐晦表达可能漏检"为已知限制 |

# 3. 功能改动说明

## 改动前
首页语音入口为占位 toast；无通话能力；内容安全仅关键词拦截 + 异常放行，无危机响应能力；记忆链路仅有 Step6 服务于文字对话。

## 改动后
新增语音通话全链路（发起-接通-通话中-挂断-会后处理）、新增独立语音记忆炼制服务、新增危机内容识别与用户侧资源展示能力。三者均为新增独立模块，不修改 Step6、AGE003、现有 Doubao 文字对话链路的既有代码。

## 核心变化汇总

| 维度 | 改动前 | 改动后 |
|---|---|---|
| 语音入口 | 占位 toast | 首页主入口 + 聊天页图标入口 |
| 通话计费 | 无 | 秒级余额制，后台可充值，耗尽时用角色化文案包装，不暴露系统措辞 |
| 通话安全 | 无 | 静音10秒兜底挂断 + 危机关键词检测 + 资源展示 |
| 记忆链路 | 仅 Step6（文字） | Step6（文字，不变）+ 独立语音记忆服务（借鉴同范式） |
| 内容安全 | 关键词拦截，异常放行 | 新增 `crisis_keywords` 独立配置维度，触发展示危机资源 |

# 4. 功能详细逻辑

## 4.1 通话发起
用户点击主入口/次入口 → 校验剩余余额：
- 余额 > 0：建立语音会话，8秒内未成功接通 → toast"可能手机没有在手边，要不等会再试试？"（不建立会话）；接通成功后由林小梦先开口
- 余额 = 0：不建立会话，toast提示"对方当前不方便接电话，可以打字留言哦"
- 麦克风权限被拒绝：仅阻断本次发起，不影响文字聊天等其余功能

## 4.2 通话中
- 实时语音双向流（豆包端到端实时语音大模型）
- 按秒扣减余额，静音检测持续运行（双方连续10秒无有效语音 → 强制挂断）
- 网络异常：先进入重连宽限窗口，宽限期内恢复则继续通话，超时未恢复才计为通话结束；与静音判定逻辑分开，不合并处理
- 余额扣减至 0：不提前预警，通话即时停止，停留在通话页面，5秒倒计时，toast提示"对方信号不好，可以文字继续哦～"

## 4.3 通话中的危机检测
每轮 ASR 转写文本 → 命中 `crisis_keywords` → 触发两个并行结果：
1. 原始文本写入独立危机存储（不进记忆系统）
2. 通话界面展示非阻断式资源提示卡片（系统级样式，非角色语气）："如果你正在经历困难，这里随时有人可以聊聊：全国心理援助热线 12356（24小时，免费）[一键拨打]"，本通话内首次命中展示一次，保留常驻小入口可重新查看；不因触发而中断/限制通话

## 4.4 挂断与会后处理
通话结束 → 转写文本进入独立语音记忆炼制服务 → 借鉴 Step6 的 11 字段抽取范式 → 按 C15 两档规则处理 → 写入共享 DashVector 索引（打 `source=voice_call` 标记）→ 关系成长按 C11/C26（有效通话日+里程碑，具体分值：首通+5/有效通话日+5/单日≥10分钟额外+10/每日上限20）更新

## 4.5 危机资源展示（详细设计见 4.3，C17）
系统级 UI 卡片，与角色语气/聊天气泡明确区分开的视觉样式；展示内容为全国统一号码 12356，不展示地区分线或个人电话；不影响通话继续。

## 4.6 语音人格 Prompt 与边界规则
语音角色行为由独立的语音人格 prompt 驱动（不复用现有文字对话 `prompt_builder.py`，但结构上参考其分段方式），需包含：
- 基础人设（复用 C3 核实后的统一人设基线，人格卡文案需等 C3 技术债解决后再定稿，不提前写死）
- AI 身份边界（C19：永不承认AI）
- 情感边界规则（C25：不把粘人表现为控制/嫉妒/施压）
- 该 prompt 需支持后台编辑，见第 10 节

# 5. 边界情况

| 场景 | 处理方式 |
|---|---|
| 8秒未接通 | toast"可能手机没有在手边，要不等会再试试？"，不建立会话 |
| 麦克风权限被拒绝 | 仅阻断本次语音发起，文字聊天等其余功能不受影响 |
| 余额为 0 时尝试发起通话 | 拦截，不建立会话，toast"对方当前不方便接电话，可以打字留言哦" |
| 通话中余额耗尽 | 立即停止，5秒倒计时，toast"对方信号不好，可以文字继续哦～" |
| 双方连续10秒静音 | 服务端强制挂断 |
| 通话中网络异常 | 先进入重连宽限窗口，超时未恢复才计为通话结束，与静音判定分开 |
| 危机关键词命中（仅限自伤/自杀） | 见 4.3，独立存储 + 展示资源卡片，不挂断不限制 |
| 危机检测范围外的风险内容（性内容/跟踪控制/诈骗等） | ⚠️ 已知未覆盖，当前版本不处理，见第 9 节已知限制 |

| 未成年人 | 不做验证，用户自主声明18+ |
| 用户要求删除某次通话 | 不提供该入口（MVP不做），记忆已按来源标签分类，后续可批量处理 |

# 6. 数据结构（草案，供开发阶段细化）

- `voice_call`：call_id / user_id / start_time / end_time / duration_seconds / end_reason（正常挂断/静音超时/余额耗尽）
- `user_voice_balance`：user_id / remaining_seconds / last_updated_by（后台充值记录）
- `voice_memory_candidate`：借鉴 `memory_llm_service.py` 现有11字段结构 + 新增 `source_call_id` / `asr_confidence` / `sensitivity_tier`（一/二档）
- `crisis_incident_log`：call_id / timestamp / matched_keyword_category（不含逐字内容摘要，逐字原文另行独立存储，不与记忆表混用）
- Redis 新增 key：`crisis_keywords`（危机关键词列表）、`sensitive_field_types`（第三方隐私类型列表），均沿用 `banned_keywords` 的可配置模式

# 9. 已知限制（明确记录，非当前版本处理范围）

| 限制项 | 说明 |
|---|---|
| 危机检测覆盖范围 | 仅覆盖自伤/自杀倾向（C23），未成年人性内容、性暴力、跟踪控制、医疗危机、诈骗等类别当前版本不处理 |
| 危机检测方式 | 纯关键词匹配（C24），隐晦/间接表达可能漏检，未叠加语义判断层 |
| 单一供应商风险 | 语音底座不做级联备用（C9），若豆包端到端语音接口变更或下线，当前无 Plan B |
| 成功指标体系 | 不采用调研文档原有的完整埋点体系（P50/P95延迟、打断生效率等），Phase 0/1 阶段以人工主观评分代替，规模扩大后再补充正式埋点 |
| 小程序迁移可行性 | 若未来迁移至微信小程序，录音上传链路（`RecorderManager`+`WebSocket`）成熟可行；但实时语音**播放**链路在小程序内有已知卡顿/不支持流式播放的限制，需专项验证与适配，非本版本范围 |
