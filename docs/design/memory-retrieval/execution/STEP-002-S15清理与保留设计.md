## 6. 持久协议、T0与依赖顺序（PLANNED）

### 6.1 一次运行与阶段记录

共享DDL以[主技术方案](STEP-002-技术方案与参数定稿.md)为唯一准据：`memory_reset_run`唯一`(environment_id, reset_key='S15')`，禁止换run_id/清单hash绕过已完成；`memory_reset_item`以`kind='phase'`登记阶段，以`kind='resource'`登记资源断点/保留hash/结果；`memory_runtime_fence.target_epoch`关联新业务时代。完成记录及其资源不属于本次删除范围。

阶段只前进或在未完成阶段续跑；完成事实单独持久事务提交并读回后才可开放。跨MySQL/Redis/DashVector/文件不能声称原子提交。提交结果未知先读持久状态与资源后置事实；不得盲目重清。已COMPLETED但未OPENED只继续开放；OPENED后只前向修复或恢复含新增数据的新库，不能恢复旧内容、回切旧库或再次清空新数据。

1. 固定环境、同Cluster精确新旧Collection和全部partition、SQL schema指纹、各表字段、Redis键、日志/对象/进程清单，dry-run预览影响；预览不是最终保留基线。

3. 持久设置维护fence/清理run和旧call cleared_run；维护态先将target_epoch按本run推进一次、拒绝旧epoch，再按§2.1登记旧控制身份并收敛目录deleted、关闭已核清保护、清payload/诊断快照，保留代次/回执/计数历史；专用语音清理保留终态统计。清voice replay/trace，清job失效消息引用及turn/call/crisis正文，不通过旧delete_call改终态。

### 6.3 保留摘要

T0后、任何删除前，按稳定主键排序规范编码每张保留表/共享行：字段名、值、NULL、类型与时间精度一致；逐行hash→表级hash，同时记录ID集合/行数。姓名昵称、level/growth、额度、关系各数值、timeline next_seq、日记/朋友圈及图片引用、配置、账本/统计必须覆盖。受定向清理影响的行分别计算“保留列摘要”和“待清字段清单”，不能只比全表行数。

语音保留字段摘要使用§3.2与§4的明确投影；合法设置的deleted/fence/cleared_run/正文清理标记排除等值比较并验证目标值。审计表保留元数据、relationship保留所有非六字段。输出摘要不含业务正文、认证密钥或低熵敏感字段明文；摘要仅在授权维护证据域保存。保存T0前排空/结算变化与T0后清理变化的分界，避免把正常结算错报清理破坏或掩盖清理破坏。
