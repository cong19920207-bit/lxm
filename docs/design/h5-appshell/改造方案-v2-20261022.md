## 2. 架构和生命周期

### 2.1 职责划分

| 层 | 持有内容 | 生命周期 |
| --- | --- | --- |
| AppShell | 页面容器、共享服务、全局错误与真实文档生命周期 | 当前文档启动至真正销毁；BFCache 冻结/恢复另行对账 |
| Router | 路由表、导航代次、守卫、URL/history、页面装载、滚动/焦点与弹层返回顺序 | 一个文档一个实例 |
| AuthService/API | 身份快照、凭据代次 authEpoch、认证 attempt、账号通知与请求上下文 | 全局唯一；接受新 token、退出、失效均淘汰旧异步副作用 |
| BGM 服务 | Player、Controller、Output、Catalog、Session、Ducking、Media、Preparation | 全局唯一；普通路由切换不销毁 |
| 全局音频协调 | 通话/媒体占用与未确认清理归属 | 占用结束且清理条件成立后释放 |
| 页面模块 | 当前页 DOM、业务数据、请求等待、事件、观察器、RAF、计时器 | 每次进入创建，离开清理 |
| 页面 BGM 适配 | 首页面板/内容页气泡、避让区域、弹层遮挡 | 随当前路由挂载/卸载；不拥有实际音频 |

全局服务不直接依赖某个页面 DOM。页面通过注入的服务接口调用，不读取其他页面内部变量。

### 2.2 页面模块协议（计划接口）

拟采用 `mount(context) -> { unmount(), captureState?() }`，模块加载与页面运行实例分开。

`context` 至少包含：页面根节点、路由及参数、进入原因、Router、共享服务、账号快照、authEpoch、routeEpoch、AbortSignal、资源清理登记器和允许恢复的页面状态。

- 代码模块可按需加载并缓存；页面运行实例默认卸载，不整站 keepalive。
- 页内 DOM 查询以根节点为范围；全局弹层、键盘等能力经指定接点协调。
- 监听、订阅、计时器、Observer、RAF、指针捕获、页面请求全部登记归属；清理幂等。
- 离开时取消本地等待并失效旧回调；取消 HTTP 等待不代表服务端写入/生成已撤销。
- 账号变化时，私有缓存、草稿读取和旧响应检查同时核对身份及代次。共享公开目录不按账号重建。
- 不向全局派发伪造的 `pagehide/pageshow` 模拟切页；这些事件仍表示真实文档生命周期。
- 默认在新页完成必要资源加载和守卫后提交路由；过时导航不得挂载。提交时先退出旧页，再挂载新页；失败呈现可重试状态，保持 URL/当前页面一致。

### 2.3 路由与兼容

1. 保留 `/pages/index.html`、`chat.html`、`feed.html`、`diary.html`、`memory.html`、`relationship.html`、`settings.html`、`login.html` 八个地址。
2. Nginx 和 FastAPI 对这些已知 H5 地址内部返回同一 AppShell；初始化按 pathname/search 选择页面，不先跳首页再回目标页。
3. 模板源码与公开资源地址分开：拟将 `frontend/templates/` 随构建输出到 `/static/app-builds/<buildId>/templates/`，复用现有静态挂载。缺失模板/JS/CSS/Worklet 必须真实 404，不能返回 AppShell。
   未知 H5 页面建议保留两侧既有行为：Nginx 静态 404；FastAPI 未知 `/pages/*.html` 为登录兼容入口。FastAPI `/` 与该兼容入口若返回新壳，需服务端明确提供 `initialPage=login`，避免仅按未知 pathname 初始化失败。该兼容分支不得拦截 API、Admin 或静态资源。
4. 站内跳转统一走 Router；保留 `focus=unread_reply`、`just_leveled_up=true` 等已用参数。记忆/Feed 返回改用路由来源，不能依赖静态 `document.referrer`。
5. Router 统一持有 history state。页面消费参数时合并保留路由信息；音乐面板关闭优先于页面后退，避免一次返回同时触发两种行为。
6. 保留修饰键点击、新标签打开、外部链接和浏览器原生刷新；拦截仅适用于当前标签的已知站内导航。
7. 直接访问与刷新仍先过私有页门禁；服务端强鉴权不由前端路由替代。
8. 当前 Nginx `/` 进入主页、FastAPI `/` 进入登录。建议本期保持各自既有行为，仅统一已知 `/pages/*.html` 的装载机制；统一根入口另列决定项 D-03。

### 2.4 状态、样式与性能

- 状态按“路由历史条目＋账号”保存必要快照；后退恢复滚动/锚点、草稿和适合恢复的 UI。数据刷新保留现行读取规则，不新增全站私有缓存平台。
- 页面离开不新增长期保存敏感内容。现有草稿键保持兼容；换账号/退出清理按现行规则执行，不能把上一账号状态恢复到下一账号。
- `html/body` 的高度、overflow、背景等改成由 Router 明确应用并还原；页面样式限定到路由根节点，避免聊天/记忆的全屏规则污染日记/主页。
- 共享 CSS/JS 只加载一次，页面模块和大型图形资源按需加载；不为了切页方便而首屏加载八页全部代码与 WebGL。
- 主页既有 5 秒核心等待、8 秒绝对释放及减少动态策略保持。Q201 参数未启用等原保留项不在本期冒领解决。
- 页面错误只影响当前视图；模块加载失败可重试，不以跳回旧 HTML 作为隐式恢复，以免销毁全局播放器。

### 2.6 可重复装载与资源清理

- **代码缓存不缓存页面实例。** 模块顶层不查询页面 DOM、不发业务请求、不启动监听；每次 mount 创建实例并装配全部效果。HomeScene 的眨眼、发丝、倾斜、面板观察等一次性 IIFE 必须改为可安装函数，不能只清空 instance。〔E08〕
- **内联事件有迁移清单。** 静态与动态模板的 onclick/oninput/onkeydown 等改为根节点委托或实例绑定，保留坏图、IME 和移动键盘行为；不把页面函数重新挂到 window。认证表单用单一 submit 路径，非提交按钮明确 type。
- **部分挂载也能清理。** 先建立资源登记，再创建 DOM/监听/请求；mount 中途抛错须清掉已取得资源。卸载先失效回调，再停实际媒体/渲染/reader，再清事件、计时、Observer、弹层、样式；一个清理器失败不能跳过其余。清理幂等。
- **忽略回调不等于释放资源。** 无法取消的纹理、权限、Worklet 等异步返回后，须关闭/释放新取得的资源，不仅跳过 DOM 更新。跨路由必须继续的通话清理先交全局 owner，页面其余工作不保活。
- **文档属性也归路由管理。** title、html/body class/style、viewport、滚动容器切换/还原有明确表；首页和记忆页的 viewport-fit 与其他页不同，按原体验验证。页面 CSS、变量与 keyframes 不串页；共享主题只装一次。

### 2.7 导航事务与失败分支

区分 navId（每次导航意图）和 routeEpoch（已提交页面实例）。准备一个最终取消的导航，不应无故废弃仍显示的旧页；账号变化另行失效私有任务。

| 环节 | 具体规则 |
| --- | --- |
| 准备 | 仅取当前 build 的模块、模板、样式；有界等待/重试；不挂载、不开 Feed enter、不执行写操作 |
| 提交前 | 再验 navId、最新身份、离开约束；过时结果不得挂载；通话离开按 D-02 |
| 提交 | 先安装目标所需音频 blocker，再捕获快照、失效/卸载旧实例、切换 URL/history/文档属性并挂载新页，最后统一恢复对账 |
| push 导航准备失败 | 保留旧页及旧 URL，展示本次失败；新重试有新 navId |
| 提交后挂载失败 | 清部分实例，在目标 URL 显示重试状态；重试新建页面，不重建播放器 |
| popstate | URL 已变化，不另 push；加载失败在目标 URL 显示错误。若 D-02 需要撤销后退，按条目位置回补一次并抑制回补循环，不能连续盲目 back/forward |
| 同路径参数变化 | 路由声明是否更新或重挂，不能漏 focus 等参数，也不无意义重复 push |

history.state 只保存带命名空间的 build/schema、entryId、位置和非敏感路由/弹层标记，合并保留其他字段；不放 token、密码、聊天正文或完整私有列表。初始条目 replace 初始化，旧/空 state 安全回退。浏览器可能持久化 history state，私有 UI 快照应单独放有界内存。〔W03〕

原本参与返回的音乐面板统一由 Router 管理，关闭按钮、Back、路由退出、通话触发收起共用一次事务。路由正在提交时不得由旧面板再独立 history.back。其他弹层只统一清理，不擅自为全部弹层增加历史条目。滚动恢复选定 Router/浏览器的唯一主导方，验证嵌套容器、图片迟到锚点与焦点。〔E06〕

### 2.8 身份、401、共享弹窗与退出

**同账号新 token 也使旧请求失效。** principalId 表示用户；authEpoch 表示当前接受凭据的代次，登录接受 token、退出、有效 401 失效时递增；匿名认证另有 authAttemptId。不能只比 user_id。保留存储不可读与临时内存身份语义，不把未知身份当成已确认访客。〔E02〕

共享 request、直接 fetch、SSE、状态核实、语音控制都捕获请求主体/代次/页面或全局 owner；在提交 UI、清 token、导航、弹窗、toast、缓存写入前复核。

401 按“复核请求→失效当前凭据→清私有状态→执行原四类策略”处理。它要记录**自身清 token 后**的事务代次，并在每个 await 后确认没有更新身份/路由接管。去重锁按本次失效事务释放，不能将 protectedLoginRedirecting 留为文档终生 true；第二次真实失效仍正常执行。〔E02〕

| 入口/状态 | 补充规则 |
| --- | --- |
| 共享登录弹窗 | 持有 modalSession/authAttempt/ownerRoute；关闭、替换、所有者离开，均失效本地旧提交结果/回调并清敏感字段、焦点计时。不能撤销已在服务端发生的注册 |
| 一次认证成功 | 只由一种机制恢复当前页资源，避免 AuthService 事件与旧 onSuccess 各恢复一遍 |
| 弹窗注册 | 保留直接接受 token 并恢复当前页一次 |
| 独立 Login 注册/重置 | 保留回登录面板、填账号、不自动登录；独立登录成功去主页 |
| 退出确认 | Promise 带身份/页面；卸载或身份变化以取消结算；确认后和 logout 返回后再次校验，旧退出不能清新身份 |
| 私有清理 | 退出、账号替换或有效身份失效时，AuthService 清理旧无账号归属的 `chat_draft` 及明确列入清单的私有 UI 状态，即使 Chat 未挂载；按用户隔离的 `chat_submissions:<user>` 恢复索引遵循现有字段白名单与保留期限，不因卸载或同账号凭据更新一概删除；同账号凭据更新保留有效草稿，设备偏好保留 |
| storage 事件 | 保留已有跨标签身份/偏好对账；同文档用显式通知，不新增多标签音乐同步 |

两个注册入口的成功语义不同，已有契约明确如此，不因共用表单改变。〔E03〕

### 2.9 恢复快照与在途业务

- 快照按 entryId＋principalId＋schema 隔离；身份变化清私有快照。数量/估算体积上限与淘汰规则在 APS-01 登记，失效或超限回到原读取；不保存 DOM、reader、计时器、WebGL、密码或认证提交。
- 离页只结束本地等待，写入结果未知不自动重发。用原请求身份/查询接口核实；服务端已完成的事实通过重新读取恢复，不由旧回调写新页面。
- Feed SSE 不补离线历史，enter 会更新最后进入时间并影响 badge。按原进页语义，每次有效进入时，访客仅请求公共 Header/List；已登录当前身份执行 enter 与私有列表初始化。预取或未提交导航不执行 enter；提交后初始化失败的重试仍沿用该进入事务去重。快照可作临时 UI，随后核对列表/未读及失效内容，focus 优先；登录恢复与初始化共用去重，避免双 enter、双 SSE。〔E04〕
- Feed 曝光/停留不从快照续计；旧 Observer 已排队回调在发 POST 前仍查归属。返回须重新满足原 60%/3 秒条件；点赞或评论丢响应时通过读取核对真值，不自动重放本次写操作，不阻止核对后用户发起新的合法交互。
- Chat 回页沿用 restore，不用 start 生成新 ID：保留用户＋operation＋request_id、generation、revision、原绝对截止和耗尽状态，只有现行协议允许的新有效代次才改变截止。UI 草稿/锚点和原提交索引分离，不新增在索引保存聊天正文。〔E05〕
- 日记已读、升级参数已消费等有效事实不被旧快照倒退；锚点条目已不存在时安全回退。

### 2.10 文档隐藏与 BFCache 对账

| 场景 | 规则 |
| --- | --- |
| 普通站内导航 | 不调用文档 suspend、restoreSession 或播放器 discard；只换页面实例 |
| hidden→visible | 按原停声规则；恢复前核对最新意图、阻断、身份和偏好；截止按真实时间检查 |
| pagehide/冻结 | 全局保存一次并停止相关资源，失效旧异步工作；冻结前遮蔽不应直接恢复的私有视图 |
| pageshow persisted=true | 统一事务：身份/history/存储 revision/通话占用对账→安装 blocker→恢复当前视图→最后决定声音；旧检查点不得先覆盖新状态 |
| 真正文档销毁 | 清全局资源；客户端不能保证继续执行远端清理，unknown 依赖既有服务端收敛/恢复机制 |

pageshow 与 visibilitychange 共用幂等恢复代次，不能各自重复 seek、取数或复活冻结前导航/权限任务。真实 BFCache 要离开当前文档再返回并观察 persisted；Router Back 和合成事件不能代替该证据。〔E06/E07、W02〕

### 3.1 稳定输出需要新的曲源归属

当前 Controller 以 output/retiring 对象身份过滤旧回调，旧切换 finally 会 silence/destroy；Output 的 metadata 可触发 seek。复用物理 audio 后不能照搬这一隔离方式。〔E06〕

分离“文档级物理输出”与“本次曲源逻辑句柄”。换源递增 sourceGeneration，play/resume/fade、metadata/ended/error、seek、超时和 finally 均核对归属；旧句柄只能取消自己，不能清当前 src 或断开共享图。先失效旧操作，再按现行淡出/停止规则切源；同 trackId 的 mediaVersion/URL 变化也区分。下一首准备元素独立、静音、最多一个，不混入主输出。

sourceGeneration 在操作发起时捕获，不能在回调执行时读取最新值后反向认领。复用 audio 的原生事件本身不带曲源代次，事件适配层还须结合当前装载阶段、预期资源与媒体实际状态过滤过时事件；不能仅凭事件名或当前 generation 执行 seek、下一首或故障恢复。R-10 覆盖旧事件已排队、换源后才分发的顺序。

页面卸载和旧曲源句柄不得 dispose 共享物理输出。文档级所有者负责物理输出销毁；必要的故障降级/重建也由其串行停止并清理旧输出、失效代次后替换，旧清理不能影响替代输出，重建仍检查许可。正常路由与正常换曲保持物理输出复用。

### 3.2 阻断与租约释放顺序

blocker 按 owner 句柄聚合；activityId 附加页面实例，旧句柄不能释放新页面同名活动。路由提交先安装目标 Login/access/call 阻断，再释放旧页，最后统一 reconcile 一次；解除 blocker 不改变 paused/closed/recoveryRequired。

页面实际视频/录音/短音频停止后再释放租约，保留普通媒体默认人工恢复与短音频恢复的差异，不能统一 resumeAllowed=true。离开 Login 没有真实 visible 事件，必须明确触发合法恢复对账；此前暂停/关闭仍保持。全局 Preparation 通过注入状态判断主页加载避让，不直接读取页面 DOM。〔E06〕

短音频既有有界超时仍保留，但超时路径须联动所属活动的停止/取消，并使晚到开始回调失效；不能只移除租约而让失去归属的真实音源继续播放。停止失败或结果未知时按实际资源状态处理，不假定已停声。

### 3.3 通话停声、退出和未知结果交接

支持能力检查通过后获取通话占用，关闭本次 BGM 意图并完成**实际停声屏障**，再允许 getUserMedia。普通淡出 pause、已发通知或已提交 HTTP 不代表停声；旧 play Promise 不能在屏障后重新出声。不支持环境保留原拒绝行为。〔E07〕

离页统一处理 permission、incoming、重连、socket、heartbeat、Worklet、麦克风、播放节点和 progressTimer：先失效旧回调，在仍可用的控制通道发原取消指令，立即停止本地音频/采集并关本地资源；远端 end/核实不能阻塞本地停声。不能伪造未实际播完片段的 played/completion ACK，通话音频图仍独立于 BGM。

页面卸载前交给全局协调器的不是 occupied 布尔，而是完整待核实记录：

| 内容 | 必要用途 |
| --- | --- |
| ownerId、原主体、authEpoch | 防旧通话影响新账号/新占用 |
| attemptKey、原请求身份、可空 callId | 区分创建未知与已知通话，按原协议核实，不能新建 key 掩盖未知 |
| 未决权限/资源 Promise、本地 close 结果 | 晚到麦克风/context/Worklet 仍关闭并记回原 owner |
| 远端 cleanup 状态和证据 | 分开判断业务终态、结算、租约清理 |
| 原协议核实能力 | 卸载旧 DOM 后仍可核实；回页只订阅已有工作，不重新拨号 |

切账号后不得用 B token 代办 A 的查询/结束；无合法授权时保留 unknown，交现有服务端机制收敛。页面消失、socket 关闭、超时、401、显示结束结果，都不单独证明远端清理完成。当前 renderResult 的释放路径必须对照语音 cleanup 契约再迁移。只有本地及所需远端条件均成立，才释放该 owner。〔E07〕

D-02 只决定离开确认的交互；无论如何选择，都要完成停声与交接。全局 owner 仅保证跨当前文档内路由存活，不保证真正销毁文档后 JS 继续运行。

### 7.6 门槛与建议参数

- **硬门槛：** 旧身份副作用为零；单次有效用户操作只产生一次业务提交；导航不主动暂停/重播/seek；未知通话不误释放；页面资源清理到声明基线；必要资源不混版/404；原权限与接口语义不回归。
- **建议参数：** 资源循环可先用每页20轮、暖机后固定idle点对比，研发在APS-01根据设备和成本校准。页面timer/RAF/listener/observer/subscription/reader应清零；明确允许的全局服务/模块代码缓存另列白名单。JS堆与GPU受GC和驱动影响，不要求精确字节归零，用资源归属计数及稳定趋势判断。
- 快照数量/体积上限、模块等待超时、旧资源保留窗口、性能预算均为工程待冻结参数，不写成已确认产品值；先测旧版本基线再定。已有主页5秒/8秒与聊天服务端时间规则保持，不新增Q201生产阈值。

## 8. 发布、回滚和契约同步

### 8.1 资源版本与公开出口

1. 原八个 `/pages/*.html` URL 保留，由精确路由返回 AppShell；源模板不直接当完整页面返回。建议产物统一放 `/static/app-builds/<buildId>/`，与现有 /static 挂载兼容；实现可以选等价hash寻址，但须在APS-02冻结。
2. 每个壳启动即锁定buildId/manifest，覆盖模块及其import、模板、CSS及url()、vendor、图形资源、Worklet。不能只给bootstrap加?v，而让动态依赖继续走可变URL。模板内相对路径按壳文档解析，构建时须转换/解析验证。〔E09〕
3. `voice-audio-transport.js` 当前固定addModule路径必须由版本资源描述提供；`voice-playback.js`、`voice-microphone-worklet.js` 和Three.js链一并纳入。曲库/签名媒体URL仍按其独立mediaVersion/有效期工作，不冻结为前端静态曲库。
4. 壳HTML重验证；版本资源URL内容不可变，可用长期缓存；不存在的资源真实404并返回正确MIME。实现时验证精确H5规则不抢占API/Admin/SSE/WS/BGM上传location。

### 8.2 切换与回滚步骤

当前Compose让backend与Nginx挂载同一可变frontend目录，Dockerfile又包含镜像内副本；因此一次覆盖目录或分别重启两服务，并不天然等于整套原子发布。〔E10〕

1. **准备候选。** 登记buildId、资源清单/摘要、镜像或挂载来源、入口配置、测试结果及旧版本恢复点；先把完整不可变资源投放到两个入口都能访问的位置并校验。
2. **兼容预置。** 新页面handler/静态寻址先支持新旧完整构建，再激活新入口。确定当前部署究竟采用bind mount还是镜像文件，不能只验证其中一个。
3. **切换入口。** Nginx与FastAPI分别有明确激活点及失败恢复动作；每个新壳锁定一套资源。若做会话灰度，必须先实现两侧一致的版本选择机制；未实现前使用独立验收环境验证整套，再切默认入口，不宣称已具备灰度。
4. **处理在途任务。** 首次FastAPI路由更新可能重启承载语音/API的backend，发布计划须选择兼容更新、排空或受控窗口，并记录实际通话/聊天恢复预期；不能因“业务接口不改”就承诺无服务中断。
5. **验证旧会话。** 发布后旧壳首次懒加载Memory/模板/Worklet仍成功；新会话取新构建。旧多HTML文档不会在后台自动变成AppShell，真实跨文档切换仍按原规则处理。
6. **回滚。** 回切完整旧入口；同时保留已经打开的新壳所需新资源。回滚不是删除新资源目录。记录存量会话支持窗口与回收条件；未定窗口不擅自清理，不能以暂时无请求证明没有旧会话。
7. **验证存储。** 优先保持旧BGM/聊天键与schema兼容，新壳快照用独立键/版本；按旧→新→旧双向测试。未知偏好版本当前可能回默认（autoplay默认true），未知session又采取保守暂停，所以“不清空storage”并不足以保证回滚意图。〔E11〕

无需新增数据库迁移。已有BGM迁移、媒体存储和Admin配置不因本次前端迁移自动重做或修改。

### 8.3 文档收口与权限边界

实施后再同步H5/BGM生命周期、入口/缓存/资源版本与验证边界；语音只同步实际退出/清理接点，聊天只同步实际客户端恢复变化。补齐缺失契约时保留来源和代码差异，不将附件未核实的V1.3交付声明改成现行事实；更新代码面映射、索引和manifest，不重写历史结项记录。

生产发布、生产数据及外部配置变更不由方案修订自动授权；发布动作需以具体版本、验证结果和回滚动作作为审阅对象。本轮仅交付方案。
