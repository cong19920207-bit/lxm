## 发布动作（待授权执行）

开发交付已按 UD-DEV-CLOSE-20261023 结项，27步按本次批准范围完成。该决定不放行生产：`evidence/step-026/development-closure-decision.json` 的上线前必验清单仍须补齐，随后另行确认实际部署对象与窗口。

以下是当前已核实本机拓扑的审阅命令。生产主机、镜像 ID、旧配置副本和维护窗口须在正式授权对象中绑定；不能直接把本机路径当生产路径。

1. 将已审核源码固定为部署快照，保留当前 backend 镜像 ID 与当前运行 Nginx 配置。构建候选镜像而不启动：`docker build --platform linux/amd64 -t lxm_for-backend:appshell-016f0dcb7b08f537954081fd .`。登记构建出的镜像 ID、源码摘要；工作树含本任务之外已有改动，发布审阅须确认完整镜像范围，不能宣称仅含本任务改动。
2. 完整预置构建目录，保留旧静态资源。对将要挂载的目录运行只读校验：

   ```sh
   python3 scripts/release_appshell.py inspect --frontend-root frontend --build-id aps1-016f0dcb7b08f537954081fd
   ```

   工具逐项验证 manifest/schema/buildId、资源路径/长度/SHA256、依赖闭包、入口配置/SRI/摘要。`inspect` 不修改入口。记录 `current`；初次部署预期为 `absent`。
3. 首次后端 handler 更新采用**受控维护窗口**：停止接纳新的聊天/通话，通知既有会话使用者并结束或等待当前任务，记录残留在途 ID 和状态。当前没有新增全站排空控制器；不能仅看短时零流量认定排空。受影响窗口和入口限制动作须由部署授权明确。用只含 `backend.image` 的 Compose override 固定候选镜像，运行 `docker compose -f docker-compose.yml -f <已审核override> up -d --no-deps --no-build backend`。该步骤会替换实际后端，不能在开发验收中顺便执行。
4. 保持 `app-entry.html` 缺省，分别确认 :8000 与 Nginx 旧页面/API 正常且候选版本资源可取；校验 `docker exec lxm_nginx nginx -t` 后才 `docker exec lxm_nginx nginx -s reload`。新版 FastAPI handler 与 Nginx 已兼容未激活旧页，再进入激活步骤。两服务更新不是原子操作。
5. 对共享前端目录进行一次完整入口切换：

   ```sh
   python3 scripts/release_appshell.py activate --frontend-root frontend --build-id aps1-016f0dcb7b08f537954081fd --expected-entry-sha256 absent
   ```

   若原本已有完整壳，改用审阅时记录的实际旧入口摘要；比较不匹配即停止。工具使用协作锁和原子替换，自动按摘要保存旧入口至 `.appshell-entries/`。该原子性只覆盖同一目录中的入口文件，不覆盖镜像部署、Nginx reload、数据库或多台主机。
6. 在 Nginx 与 FastAPI 两个 origin 各检查八个页面的直进/刷新，入口 SHA、no-cache；检查版本资源 200/304/immutable、缺失资源 404、API/Admin/SSE/WS/上传旁路。打开旧壳的 Memory/语音首次加载、新会话取新 build；任何一侧失败立即按下文恢复旧入口，继续保留两代资源。没有一致灰度选择器，本版本不宣称支持会话灰度。

## 失败与回退

- 初次激活回旧独立页：

  ```sh
  python3 scripts/release_appshell.py deactivate --frontend-root frontend --expected-entry-sha256 12e5548e2173f7a78cb6c7ba6c60f6524cab611f29464cbcbe29fbb3ddca06db
  ```

- 已有旧壳时，`activate --build-id <原完整旧build> --expected-entry-sha256 <当前入口摘要>`；旧 build 必须重新完整校验。两入口共用同一物理目录时同时读取回退后的文件；仍分别做 HTTP 探测。
- Nginx 配置更新失败：保留/恢复授权前记录的旧运行配置，`nginx -t` 后 reload；backend 已更新但尚未激活时仍可返回旧 HTML。FastAPI 镜像更新失败：Compose override 指回记录的旧镜像 ID，恢复该实例，再核对两入口。回退镜像也有中断窗口。
- 回退不删构建，不改用户 storage。旧独立 HTML 使用当前兼容库；STEP-024 已验证旧→新→旧。未知自动播放偏好安全关闭并保留未知值，未知 session/双写失败显示提示；原聊天 ID、期限和耗尽状态不重发、不重置。

## 在途任务与支持窗口

- 隔离演练通过原生 SSE/WS 连接实际后端进程，再重启该临时进程；Chat/VoiceEntry 是实际客户端，服务业务结果和权限明确受控。证据不能证明真实 Provider、数据库结算或生产恢复，也不承诺零中断。
- 语音重连当前要求原进程 owner，不能跨进程接续 Provider。重启可能中断通话；本地采集/输出停止，沿原 call 核实结果，未知清理保持占用，不重拨、不自动重开 BGM。生产应在维护窗口结束通话，不以短重连窗口代替排空。
- 文字客户端沿原 request/generation 和绝对期限 GET 核实，不重发 POST；原服务端持久 dispatch/lease/reconcile 规则保持。`chat_lifecycle_runtime.stop()` 停止扫描器，不等价于所有外部在途请求完成；不能因 handler 改动小就承诺无影响。
- 支持窗口冻结为：**至少保留当前、上一代，以及任何尚可能有活跃文档的构建；没有自动到期删除。** 没有可证明会话全部结束的机制时无限期保留。回收必须有所有旧文档已结束的证据，或另行批准的受控重新载入窗口并完成必要兼容核验。日志暂时无请求、TTL 到期、回退成功均不构成回收证据。
- `release_appshell.py` 无 prune 功能，不删除旧源码/资源，不触发后端重启、Nginx reload、数据库迁移或 OSS/CORS 修改。
