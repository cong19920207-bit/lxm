## 1. 审核结论与本轮决策

### 1.1 总体结论

已确认的主流程能够成立：**一个全局歌单，主页唱片入口，其他页面轻量气泡，跨独立页面恢复状态，后台维护素材。** 无需为了 V1 把整个 H5 改成单页应用，但也不是只修改一个主页按钮：前端共享播放能力、接入页面、公开歌单、账号偏好、后台管理、转码和资源生命周期均在范围内。

V1.0 审核稿已经写入播放状态、关闭/恢复条件、公开交互、账号同步缺口、音频兼容和错误回退等修正，并将四个产品边界列为待确认。本版落实用户对 Q01–Q03 的确认，并按 Q04 的运营诉求取消周期轮询、取消自动延迟删除队列，统一更新正文、参数和验收要求。

**完成的是需求逻辑与文档修订，不是生产代码修复。** 真机音频兼容、接口负载、转码效果和正式功能回归仍需要实施后验证。

### 1.2 Q01–Q04 决策落地

| 编号 | 用户本轮决定 | 本版业务规则 | 参数/实现说明 |
|---|---|---|---|
| Q01 | 在现有带“退出登录”的设置页面增加开关 | 在 `frontend/pages/settings.html` 增加“下次打开时自动播放 BGM”，默认开启；不另建设置页，不放到主页音乐面板；访客也可使用 | 只影响新访问自动启动，不停止本次已开始的音乐；放在公开区，不跟随私有设置一起隐藏 |
| Q02 | 按审核稿推荐 | 同源标签页会话为“本次”；刷新、站内跳转、后退不重置关闭状态；通常关闭标签页再打开算新访问，浏览器恢复旧会话时仍尊重关闭状态 | 只保存本机临时状态，不做跨设备播放接力 |
| Q03 | 按审核稿推荐 | 访客登录不打断本次播放；不整包覆盖已有账号偏好；登录后的新操作按字段同步；账号无 BGM 偏好时才以访客值初始化 | 账号缓存隔离；旧响应不能覆盖新操作 |
| Q04 | 可以隐藏后再删除，但要按实际运营能力简化；不需要复杂删除限制，只检查操作时是否已超过等待时间 | “隐藏”与“下架”是同一个动作；移出公开歌单但保留后台记录/音频。取消每分钟轮询，改为事件触发检查并复用缓存。已发布曲目隐藏满等待时间后，由有权限的管理员手动二次删除 | 不等待在线用户逐个确认，不加审批流、回收站、在线人数检查或自动定时删除任务；24 小时等待、5 分钟缓存复用为建议初值 |

**Q04 对 V1.0 的覆盖关系：** 删除“活跃播放期间每 60 秒校验”，也不采用“先接受删除、以后由队列等到 24 小时清理”的流程。改为“先隐藏 → 超过等待时间 → 管理员点击删除 → 当次检查时间并执行”。

**参数口径：** 用户确认的是业务原则，没有逐项指定秒数/小时数。24 小时沿用审核稿的建议，5 分钟是本版为减少重复请求提出的缓存有效期，二者可在实施评审中调整；不宣称是现网配置或容量测试结果。

| A06 | `canplay` 被解释成稳定播放，且默认仅靠 HTML Audio 就能完成音量/渐变 | `canplay` 仅是可开始播放信号。精细音量与渐变需评估 Web Audio 增益链；媒体播放及音频上下文均须实际可运行 [S04]–[S07] |
| A07 | “96 kbps VBR”被写成不依赖编码器的固定配置 | 保留 AAC-LC/M4A 和小体积目标；建议以 96 kbps 目标码率验收。FFmpeg 原生 AAC 的 `b` 模式与 `q` 的 VBR 模式不同，不能混称 [S10] |
| A08 | “前台全部回退完成后才允许删除”没有实现和判定基础 | 隐藏满建议等待时间后手动删除，不等客户端确认；只有自然操作触发歌单检查，不做实时全员召回或自动删除队列，见 §11.5 [S12] |
| A09 | “必须总有默认曲目”与初始空库/全部下架矛盾 | 有可用曲目时恰好一个默认；允许隐藏最后一首，无曲目时默认为空且不播放 |

| A11 | 访客可用与主页快捷入口先判断登录存在冲突 | BGM 使用独立公开交互分支，不复用“先弹登录窗”的处理顺序 [S03][S04] |
| A12 | 仅列了上传/删除按钮，没有上传失败、资源校验、默认更新并发规则 | 保留必要的失败回退、数据一致性和既有权限；删除只保留时间检查、一次确认及失败可重试，不扩建管理平台 |
| A13 | 为低频歌单变更设计常驻轮询，增加无必要请求 | 取消 BGM 歌单定时轮询；按事件检查本机缓存是否过期，仅需要时请求；同一批事件合并请求 [S17] |

## 2. 产品定位、目标与范围

### 2.1 产品定位【已确认】

为林小梦的主页和相关页面增加环境音乐，让页面有陪伴氛围。它是角色空间的一部分，不是独立音乐产品。

用户无需登录即可使用；主要操作只有播放/暂停、下一首、选曲、调音量。角色关系入口保持原位，不因 BGM 改造主页信息层级。

### 2.2 V1 包含【已确认】

| 模块 | 范围 |
|---|---|
| 主页 | “更多互动”替换为唱片 BGM；播放放大与旋转；超长歌名跑马灯；底部面板及唱片连续过渡 |
| 普通页面 | 共享纯唱片气泡；播放/暂停、关闭；右侧上下拖动；按页面决定展示 |
| 播放 | 加载页并行准备、非阻塞尝试自动播放、顺序循环、同页切歌淡出/淡入、跨页状态恢复 |
| 声音协调 | 音视频通话终止本次 BGM；角色短语音降低 BGM 音量；页面隐藏暂停、返回条件恢复 |
| 偏好 | 访客本机保存；登录账号保存长期偏好；临时进度/状态本机保存 |
| 管理后台 | 上传、名称、排序、启用/下架、默认曲目、二次删除；单一 BGM 管理页 |
| 资源 | 常见音频上传、服务端标准化、OSS/CDN、发布文件校验与清理 |

### 2.3 V1 不包含【已确认或由范围收敛】

不改成 SPA/App Shell，不为 BGM 建 iframe 外壳；不保证跨页面不中断；不新增音视频通话或 TTS 功能本身；不做按时间/天气/场景分歌单；不做收藏、歌词、搜索、歌手资料、封面体系、上一首、进度拖动、随机/循环模式设置、用户创建歌单或完整播放历史。

不接外部音乐平台，不做 HLS、离线下载、锁屏播放器或系统媒体中心主动集成；不新建分析埋点服务。不自动清理与 BGM 无关的历史技术债。

不为歌单变更增加常驻轮询、SSE/WebSocket 推送；不为曲目删除建立审批流、客户端确认机制、回收站或自动延迟删除任务。已有 Admin 权限与操作日志仍保留。音频转码可用受限任务执行，不等于要额外建设一个定时删除系统。

**工程收敛：** V1 不需要建立空的 `sceneId/timeTag` 配置模型。未来升级能力用独立模块边界承接，不以提前堆字段的方式实现。

### 2.4 后续目标【已确认】

全站具备长期存活的播放宿主，实现页面切换期间真正不断音。届时结合整体前端架构重新设计；V1 的曲目 ID、资源、偏好模型应可迁移。

## 5. 播放状态与恢复规则

### 5.1 必须区分的状态【审核修正】

“是否有播放意图”与“当前是否真正输出音频”不能混为一个字段。

| 状态/原因 | 含义 | 首页表现 | 其他内容页 | 是否可自动恢复 |
|---|---|---|---|---|
| 未启动/就绪 | 尚未尝试或等待用户操作 | 正常尺寸静止，BGM | 需要手动播放时保留静止入口 | 按启动策略 |
| 加载/缓冲 | 有播放意图但当前不可持续输出 | 不伪装正常旋转，可用轻状态提示 | 气泡静止，可暂停/关闭 | 条件仍满足时可继续 |
| 正在播放 | 媒体和输出链实际运行 | 放大、慢转、歌名 | 慢转 | 无需恢复 |
| 用户暂停 | 用户点了暂停 | 正常尺寸静止，BGM | 静止但不消失 | 否，直到用户明确播放 |
| 页面隐藏暂停 | 切后台/标签隐藏触发 | 不持续渲染动效 | 不持续渲染动效 | 返回且原意图为播放、无其他阻断时尝试 |
| 浏览器拦截 | 自动播放或音频上下文不允许 | 静止，面板可手动播放 | 静止，可展开播放 | 当前文档等待明确播放，不反复抢播 |
| 本次已关闭 | 关闭气泡或进入真实通话 | 入口仍在但静止 | 气泡不再出现 | 否，只能主页明确重新开启 |
| 资源不可用 | 歌单为空、全部候选失败等 | 入口可开空态/错误提示 | 不保留无作用的悬浮气泡 | 不无限循环重试 |

原生 `pause` 事件不等于用户点击暂停；页面隐藏导致的暂停不能覆盖用户意图。浏览器拦截也不能写成长期“关闭音乐”。[S06][S08]

### 5.2 自动播放的必要条件

只有以下条件同时满足，才允许发起或继续自动尝试：页面策略允许、页面可见、没有本次关闭标记、没有真实通话或其他需阻断的媒体活动、有播放意图、存在有效曲目及可用输出链。

本次关闭优先于页面返回、登录恢复、歌单更新、音频加载完成、曲目播完回调。用户暂停同样不得被上述回调擅自覆盖。

发生切歌、暂停、关闭、账号变化、页面离开时，旧请求和旧动画的迟到结果不得重新启动音乐。用哪种取消机制由实现确定，验收以最终行为为准。

### 5.3 会话边界【已确认，Q02】

当前同源标签页的页面会话内保存：播放意图、临时进度、本次关闭标记、气泡位置。刷新、站内跳转、后退和恢复旧页面都不将“已关闭”清空。

建议使用页面会话级持久化。`sessionStorage` 能跨刷新/页面恢复保留，通常在标签页关闭后结束；浏览器恢复或从 opener 复制状态存在边界，不能承诺“关闭浏览器必然清空”。复制标签页继承的关闭状态应保留，避免意外出声。[S09]

V1 不建设跨标签页或跨设备的播放接力/远程控制。各页面会话的临时状态隔离；多个可见窗口之间不承诺唯一播放实例。页面隐藏时仍按规则暂停。

### 5.4 主动开启与关闭面板【审核修正】

- 点击主页唱片：只打开 Bottom Sheet，不顺带自动解除本次关闭。
- 在主页按“播放”，或点击列表中的曲目开始播放：视为明确重新开启，可解除本次关闭标记。
- 收起 Sheet、点击遮罩、返回手势关闭 Sheet：只收起界面，不停止音乐。
- 气泡操作中的“关闭本次 BGM”：立即停止，隐藏气泡并写入本次关闭标记；不改变账号长期自动播放偏好。
- 通话期间禁止重新开启 BGM；结束通话只是解除通话阻断，不清除本次关闭标记。

## 6. 核心业务流程

### 6.1 加载页与首次进入【已确认 + 审核修正】

```text
进入主页文档
  ├─ 按原逻辑加载页面资源与业务数据
  └─ 初始化本页 BGM 控制器
       → 读取会话状态/本机偏好
       → 获取公共歌单及必要的账号偏好
       → 选择当前曲目
       → 准备当前音频及输出链
       → 满足条件后尝试自动播放
```

音乐先准备好：允许在加载页期间开始。页面先准备好：先进入主页，音乐继续独立准备。关闭加载层不能销毁并重建 BGM，否则会在同页制造一次多余中断。

**BGM 不加入主页加载进度的完成门槛。** 歌单接口失败、偏好请求失败、音频超时、无音乐和浏览器拦截均不阻塞主页。未显示加载页、用户直接访问子页时，也应走本页初始化，不依赖必须先访问主页。

初始化是建立本页状态，不等于无条件请求歌单/下载音频。本次已关闭或已主动暂停时，不为自动续播拉取新资源；无播放意图时可以先复用缓存展示入口，待用户明确打开面板/播放再按需获取。已关闭状态不能因加载页重建被清除。

`canplay` 只表示能开始，不能保证播完整首且不缓冲；实际播放成功后才进入正常播放视觉状态。若输出经过 Web Audio，还需确认 AudioContext 正在运行。[S06][S07]

自动播放被拒绝后，本次文档不通过计时器或任意页面点击反复尝试；保留明确的播放入口。换到新文档仍可能再次被浏览器拦截，不把曾经点击一次视为全站永久授权。[S06]

**建议补充：** 加载页阶段只要已经输出 BGM，就提供低存在感的暂停入口。此操作须保持为用户暂停，主页显示后不得自动重启。

### 6.2 曲目选择优先级【建议细化】

有效性以按 §11.5.2 获得或复用的最近一次成功校验歌单为准；客户端短时缓存不等于实时查询服务器。后台已隐藏但客户端尚未更新的延迟按 §11.5 接受。选曲优先级如下：

1. 本次会话正在使用且仍有效的曲目及检查点。
2. 当前用户最后手动选择且仍有效的曲目。
3. 后台默认且有效的曲目。
4. 配置异常时按列表顺序选第一首有效曲目；记录调试诊断。
5. 没有有效曲目：进入空态，不播放。

账号偏好存在读取延迟时，使用当前账号本机缓存；没有对应缓存且未获得账号偏好时，建议暂不自动出声，页面照常可用，手动播放不被偏好网络请求卡住。不得先用其他账号缓存播歌，再在账号数据返回时强行换歌。

**建议区分：** 最后手动选择用于新访问默认；自动顺序切到下一首只更新本次当前曲目，不不断改写账号“最后手动选择”。

### 6.3 播放、暂停、选曲和下一首

| 操作 | 建议细化规则 |
|---|---|
| 播放 | 同一会话有有效进度则续播；新会话按最后手动选择/默认曲目从头开始 |
| 暂停 | 保存进度与用户暂停意图；不隐藏气泡，不等于关闭本次 |
| 点击未选中曲目 | 视为选曲并播放，从新曲目开头开始；合法的显式选曲更新长期选择 |
| 点击正在播放的当前行 | 不重启、不暂停；保持当前播放 |
| 点击已暂停的当前行 | 视为明确播放，续播 |
| 下一首（播放中） | 按当前有效排序找下一首并播放，末尾回第一首 |
| 下一首（暂停中） | 仅更改选中曲目，从头待播；仍保持暂停，不让换曲变相绕过暂停 |
| 自动播完 | 当前播放意图仍有效时，先按 §11.5.2 检查是否需要更新歌单，再顺序进入下一首；若本次已关闭/页面隐藏/被阻断则不输出 |
| 歌单只有一首 | 自然播完从头循环；曲终同样是检查歌单是否过期的时机；“下一首”禁用，不制造无意义重载 |
| 歌单重新排序 | 当前歌曲不被重启；下一次切歌使用最新排序 |

“最后手动选择”的存储与“暂停时下一首”的细化均属于本稿评审建议，不是新增重播放器功能。

### 6.4 切歌过渡与连续点击

【已确认】同文档的正常切歌采用淡出、换曲、淡入，不做突兀硬切。用户快速连点时以最后一次有效操作为准，不能同时听到多首音乐。

【建议规则】仅加载当前选择；不下载整个列表。下一首尚未可播放时显示加载状态，允许存在等待空隙；不承诺跨曲无缝。新曲失败时提示一次，保留/恢复仍有效的旧曲；旧曲也不可用时走资源异常规则。

【审核修正】跨独立 HTML 导航不能保证旧页完整执行淡出，不能为了等待淡出延迟页面跳转。旧页尽力保存并停止，新页在恢复播放时淡入。主页唱片进入 Sheet 的连续动画只发生在同一文档，跨页面只保持相同视觉样式，不承诺真正共享元素动画。[S04][S08]

### 6.5 跨页面恢复与检查点

记录本次当前曲目、媒体版本、已播放时间、用户意图、本次关闭标记、音量和气泡位置。建议每 2 秒记录本机检查点，并在用户暂停、选曲、关闭及页面隐藏时立即记录。

新页面在获得曲目有效性和时长后恢复检查点；越界或不合法值重置为 0。音频媒体版本变化时不把旧时长/旧位置套到新文件上。离开期间不按墙钟补算播放进度。

不承诺“极短暂”具有固定毫秒上限。网络正常且浏览器许可时，验收重点是同曲续播且不是每页从头开始；拦截时可手动续播。

返回旧页面时先对账会话状态再恢复 UI，避免浏览器后退缓存复活旧唱片。移动设备可能跳过部分卸载回调，因此不能只在页面卸载时保存。[S08][S09]

### 7.2 音视频通话【已确认 + 接入边界】

当用户实际进入拨号/通话建立流程，在申请/打开麦克风和输出通话声音前停止 BGM，标记本次已关闭。取消拨号、权限拒绝、连接失败、挂断后也不自动恢复，主页可由用户主动开启。

点击当前尚未实现、仅提示“敬请期待”的语音/视频入口，不算进入通话，不应因此关闭 BGM。BGM 本期不建设通话业务；已有真实通话实现才接入真实生命周期，未实现时只保留明确接入契约和测试模拟。[S04]

### 7.3 角色短语音与其他媒体

【已确认】普通角色短语音/TTS 输出期间降低 BGM 音量，语音结束后按当前用户音量恢复。

【建议规则】降音量使用“用户当前音量 × 临时衰减比例”；不覆盖长期音量偏好。语音重叠时，最后一个活动语音结束才解除衰减。中途用户暂停/关闭/进入通话，旧语音结束事件不得启动 BGM。

同页普通带声视频或录音输入建议临时暂停 BGM；无声装饰视频不影响 BGM。该媒体结束仅解除临时阻断；当前仍可播放时才恢复。未来新增媒体播放器需要显式接入，不假设能自动识别全站所有声音。

页面无法控制设备上其他应用的声音，也不把系统电话中断等同于本应用发起的“通话关闭本次”事件；系统中断按实际可见性/输出状态保守处理。

### 7.4 页面隐藏/锁屏【已确认】

页面变为隐藏时暂停音乐和非必要动画；返回可见时，仅在隐藏前具有有效播放意图、期间没有用户暂停/会话关闭/通话阻断时尝试恢复。恢复仍受浏览器限制。

不依赖后台计时器继续运行，不承诺精确识别所有系统锁屏/杀进程情形；按浏览器生命周期与真实音频状态处理。[S08]

## 8. 前台 UI 与交互需求

### 8.1 主页入口【已确认】

替换“更多互动”整格，不变更其他四个入口的排序与关系入口位置。

| 条件 | 唱片 | 文字 |
|---|---|---|
| 正常播放 | 缓慢旋转，约 1.15–1.2 倍 | 当前曲名 |
| 暂停/未启动/被拦截/本次关闭 | 静止，普通尺寸 | BGM |
| 当前资源加载/缓冲 | 不伪装正常播放，可有轻加载反馈 | BGM；Sheet 内说明状态 |
| 音量为 0 且媒体仍运行 | 仍属于播放，不用暂停状态代替 | 曲名；面板明确标示静音 |

放大只影响视觉，不抬高整栏、不挤压相邻格、不改变格子宽度。旋转与缩放/位移动画分层，暂停冻结当前角度而非跳回初始角度。

长曲名在固定宽度内慢速跑马灯；短曲名静止。建议完整到尾后停顿，再恢复到头，隐藏复位过程；暂停、页面隐藏和减少动效模式下停止滚动。完整名称在面板可查看。

### 8.2 Bottom Sheet【已确认】

底部上滑，常规屏幕目标为视口约 40%–50%；面板有当前曲目、播放/暂停切换按钮、下一首、极简列表和弱化音量滑杆。不同时展示两个独立的播放与暂停按钮。

小屏/横屏优先保证控件可用，允许面板自适应高于 50%，歌单内部滚动；不缩到无法点击。拖动列表、音量滑杆和下拉关闭手势需要区分。

打开/收起支持明确的收起按钮、遮罩点击及适当返回操作。**按钮命名“收起”与“关闭本次 BGM”不能混用。** 返回先关面板再离开页面；具体实现不破坏原页面历史导航。

曲目列表只展示名称与当前状态，选中与实际播放须区分：当前曲目已暂停时不能展示活跃播放动效。点击整行操作，不增加封面、歌手或时长信息。

### 8.3 唱片共享视觉动画【已确认】

主页小唱片与面板唱片在视觉上是同一个对象。打开时放大、位移与 Sheet 上滑同步；关闭时反向回到第五格。播放时保留旋转相位，暂停时不额外旋转。过渡中不能出现两张同时旋转的实体唱片。

连续点击打开/关闭应收敛到最后操作，无残留遮罩、点击穿透或孤立唱片。减少动效模式下使用短渐显/渐隐和静态状态标识，不强制旋转或大幅位移。

### 8.4 角色化视觉【已确认】

整体克制，少量梦幻：深色磨砂玻璃、紫灰和粉紫微光、有限星点、柔和阴影。保留林小梦安静、清冷、都市设计师的气质，不做甜美偶像播放器、霓虹控制台或复杂唱机。

唱片使用统一角色风格纹理，不要求后台给每首音乐上传封面。建议面板标题使用不依赖时段的角色化短句，例如“陪你听会儿”，避免白天显示“今夜”的语义冲突；最终文案与参数在 UI 阶段审核。

### 8.5 悬浮唱片【已确认】

纯唱片，不带歌名胶囊。点击在附近展开播放/暂停与“关闭本次 BGM”两个操作；点击空白收回。无下一首、选曲或音量操作。

右侧上下拖动，松手吸附右边，横向不自由漂移。位置以可用高度的相对比例记录，同会话跨页面/屏幕尺寸变化后夹在安全区域内，不机械保存一个绝对像素值。

拖动不能误触点击。键盘弹起、页面底栏、全屏遮罩和屏幕旋转时重新避让；“避让”指预定义安全区与用户可拖动，不承诺自动识别任意页面所有重要内容。关闭气泡后不恢复位置动画或继续占用点击区域。

| 最后手动选曲 | 长期偏好 | 访客本机、登录用户账号同步；失效时回退，不自动把默认回退当用户新选择 |
| 当前曲目/版本/进度 | 临时状态 | 当前页面会话，本机；不跨设备续接时间点 |
| 播放意图/本次关闭 | 临时状态 | 当前页面会话；不得误同步为账号全局暂停 |
| 气泡位置 | 临时状态 | 当前页面会话；新访问使用默认位置 |
| 页面可见/通话中/短语音活动 | 当前环境 | 运行时判断；不作为长期偏好 |
| 歌单内容/版本/上次校验时间 | 缓存信息 | 同会话跨页面复用；事件触发时判断新鲜度；不是个人偏好 |

本机长期缓存必须按身份隔离，不能让账号 A 的音量/曲目被当作账号 B 的默认。退出后公共 BGM 可继续本次体验，但停止账号写入、清除私有同步身份，不把 A 的整包偏好写入访客或 B。

### 9.2 登录与同步冲突【已确认，Q03；同步细节为实现建议】

登录已有账号时，当前正在使用的 BGM 不因为服务器响应突然切歌或变音量；保留本次运行态，读取账号偏好作为后续新访问依据。访客数据不整包覆盖已有账号。

新账号/账号尚无 BGM 偏好时，可以用当前访客偏好初始化。登录后明确的选曲、音量、自动播放设置只同步发生变化的字段。迟到的读取响应不能覆盖更晚的用户操作；对同字段采用服务端版本/更新顺序处理冲突，不依赖客户端时钟决定全局先后。

音量滑动应合并保存，优先即时本地生效，拖动结束后同步，不每帧请求。同步失败不打断音乐；保留本机结果并在合理后续时机重试。不声称失败结果已跨设备保存。

BGM 偏好请求收到 401 时，遵循现有清 Token 与静默访客策略，不因公共 BGM 操作弹登录框。受保护页面自身的回退规则不变。[S03]

### 9.3 长期开关【已确认，Q01】

**位置：** 现有 `frontend/pages/settings.html`，也就是包含“退出登录/点击登录”的页面。不另建页面。使用独立公开的 BGM 偏好行，建议放在“关于林小梦”区域上方，不并入 `settings-private-sections`；原区域在访客态会隐藏。[S15]

**名称：** “下次打开时自动播放 BGM”。默认开启。说明文案应表达：“仅影响新访问；本次音乐可在唱片中暂停。”

**行为：** 访客修改本机长期值；登录用户修改对应账号偏好。开关只决定新访问是否尝试自动启动，关闭不会停止当前音乐，开启也不会立即发声或解除本次关闭。

播放/暂停、关闭气泡、进入通话均不修改这个长期开关。长期开关关闭后，用户仍可在主页主动播放，并在当前会话内跨页恢复。

**接入要求：** BGM 行不能复用“没有登录就弹窗”的旧设置动作，不能假定现有 `GET/PUT /api/user/settings` 已实现；使用 §3.2 的专用 BGM 偏好能力。退出账号后开关回显访客自身的长期值，不把退出账号的值覆盖到访客。[S02][S15]

**UI 细化建议：** 设置页仍不显示悬浮唱片。若当前确有音乐，可在 BGM 区弱化放置“暂停当前音乐”；用户暂停后可提供继续，但仅限本次未关闭的情形。本次关闭/通话终止后不提供绕过入口，回主页明确播放才重新开启。这是避免有声页面缺少就近暂停能力的 UI 建议，不新增完整播放器。

## 10. 音频资源与播放适配

### 10.1 已确认的方向

后台接受 MP3、M4A/AAC、WAV；服务器统一转换为 AAC-LC 编码的 M4A 音频，使用 OSS/CDN 发布。用户端不处理各类原始格式，也不要求运营手动填 CDN URL。

M4A 是容器/扩展名，AAC-LC 是编码；不能只看扩展名就认定上传文件已经符合发布要求。

### 10.2 建议发布标准与体积预算

下表是审核补充参数，待评审后作为配置默认值，不是用户此前逐项确认的数值。

| 项目 | 建议值/要求 |
|---|---|
| 发布容器/编码 | M4A / AAC-LC |
| 音频码率 | 目标 96 kbps；实际码控模式随编码器明确记录 |
| 首版编码器建议 | FFmpeg 原生 AAC，使用 96 kbps 比特率模式；按其文档称 CBR，不再误写为 96 kbps VBR |
| 采样率 | 44.1 kHz 或 48 kHz，选一种标准化输出并在实现评审中固定 |
| 声道 | 最多双声道；不为单声道素材伪造立体声 |
| 源文件上限 | 建议 100 MiB，为短 WAV 素材留空间；服务端与代理上传限制一致 |
| 时长 | 大于 0，建议最多 5 分钟；不接受超长整段助眠录音 |
| 发布文件上限 | 建议 4 MiB；超出不发布，提示重新处理或更换源素材 |
| 首播结构 | 启用 faststart，媒体索引前置 |
| 附加内容 | 去掉不需要的封面附件、视频轨及无关元数据；保留必要音频信息 |

按 96,000 bit/s 估算：3 分钟音频负载约 2.16 MB，5 分钟约 3.60 MB，实际包含容器开销。这里是估算，不是音质相等保证。对钢琴、低频和高频明显的素材分别试听，不能仅凭码率判断是否够好。

**编码表述修正依据：** FFmpeg 原生 AAC 使用 `b` 设置比特率模式，`q` 设置 VBR 质量；“严格 96 kbps”与“按固定质量 VBR”不应不加区别地写在一起。`faststart` 用于将 MP4/M4A 索引前置以改善开始播放的时机。[S10][S11]

### 10.3 音量与兼容性【审核修正】

30% 指应用相对增益，不是系统音量，也不是不同设备一致的实际响度。素材应在发布前试听并控制明显的音量跳变；本期不向用户提供音效或均衡器。

建议音频播放使用媒体元素按需加载，精细音量、短语音衰减、淡入淡出通过 Web Audio 增益节点实现。不能假定 `audio.volume=0.3` 在所有目标浏览器都生效；MDN 将该能力标为兼容性受限，Apple 归档资料也记录过 iOS 限制。实际支持以目标设备验证为准。[S07]

音频元素的 `play()` 成功不代表被路由到的 AudioContext 必然正在输出。若上下文被挂起，保持非播放视觉，等待明确交互；不以无声播放消耗流量来伪装已启动。

Web Audio 不绕过自动播放限制。跨域媒体接入音频图需要正确 CORS 配置，否则可能无声；该检查属于发布门槛。[S07][S13]

**兼容降级建议，需实测审核：** 精细增益链不可用时，不显示假滑杆。可提示使用设备音量；短语音期间改为临时暂停 BGM。若此降级不获接受，则将对应浏览器列为未通过，而不是悄悄降低要求。

### 10.4 加载与 CDN

只请求当前曲目；不全量下载歌单，也不将整首解码缓冲作为开始播放的必要前提。`preload` 是浏览器提示，不能当成已下载的保证。

发布 URL 采用稳定不可变的唯一文件路径，替换素材生成新资源版本，不同名覆盖。CDN/OSS 配置正确的音频类型、HTTPS、范围请求与 CORS；公开音频不附带用户 Token。

歌单元数据与音乐文件使用不同缓存规则：前者按 §11.5.2 的事件触发与短期复用策略，后者使用唯一文件路径与资源缓存。公开歌单对所有用户相同，不附带用户 Token 或夹带个人偏好；账号偏好请求单独鉴权，不能混入共享缓存。公开接口不返回上传临时路径、原文件、OSS 密钥或后台字段。

## 11. 后台 BGM 管理

### 11.1 管理页范围【已确认】

只新增一个“BGM 管理”页。支持上传、编辑名称、排序、启用/下架、设为默认、二次删除。无需独立歌单页、场景页、标签页、作者资料或封面维护。

建议表格字段：名称、处理/启用状态、默认标记、排序、发布文件大小、操作。前台不展示时长等信息，不代表后台不能使用自动解析信息检查资源。

### 11.2 最小业务数据

| 数据 | 用途 |
|---|---|
| 曲目 ID | 稳定标识，名字变化不影响用户选择 |
| 展示名称 | 前台名称；建议 1–60 个字符；安全渲染，不注入 HTML |
| 发布资源 URL / 版本 | 自动生成，避免同名缓存混乱 |
| 时长、编码、大小 | 自动提取，用于验证、恢复进度和后台检查 |
| 排序 | 全局播放顺序；冲突顺序需有稳定次级排序 |
| 处理状态 | 处理中、处理失败、就绪 |
| 发布状态 | 未启用、启用、已下架、已删除 |
| 默认曲目指向 | 全局最多/恰好一个的约束按歌单是否为空决定 |
| 创建/更新/最近一次隐藏/删除时间 | 管理追踪；删除请求按最近一次隐藏时间检查等待期 |
| 删除结果与残留文件标记 | 仅为删除失败时显示并支持手动重试；不需要独立任务调度系统 |

不要求 `isDefault` 在每行独立自由编辑；建议由唯一默认指向实现业务约束，避免两名管理员各自勾出两个默认。

### 11.3 上传与发布流程【建议细化】

```text
有权限的管理员上传音频、填写名称
→ 校验大小、真实格式、可解码性及音频时长
→ 服务端处理，管理页显示“处理中”
→ 转码并校验发布产物
→ 上传发布文件至 OSS，验证可读取与必要响应配置
→ 曲目“就绪，未启用”
→ 管理员试听并启用
→ 歌单版本更新，公开列表可读取
```

处理成功不默认强制上线；管理员试听属于本页操作，不影响用户端状态。首次启用曲目时可作为建立默认曲目的同一操作，不能先发布一个无有效默认的非空列表。

转码或上传失败时不能进入公开列表，不能假称“已上传成功”。需要重试时提供明确操作；仅为一次处理短暂保留临时源文件，成功后清理，失败/放弃也按临时文件策略清理，不作为可恢复原件长期存储。

不保留原始文件意味着以后改码率/重做音频需重新上传高质量源文件；不能承诺从已压缩发布件重新生成无损质量。

允许的扩展名、MIME、文件签名与实际解码需联合校验；生成安全文件名；禁止把任意远程 URL 作为转码输入；限制处理时间、并发及文件大小，避免音频处理拖住聊天等请求。[S14]

### 11.4 默认曲目、排序与并发

有启用且就绪的曲目时必须有唯一有效默认。设置新默认、下架旧默认和列表更新应保证对客户端呈现完整一致结果。

历史选择优先于后台新默认；管理员换默认不能导致正在播放的其他有效曲目立即切走。默认只在无历史或历史失效等回退情形生效。

下架默认且还有其他曲目时，操作中指定新的默认再提交；其他管理员同时修改时应检测冲突、提示刷新，不能覆盖成无默认或重复默认。

初始空库允许默认为空。允许隐藏最后一首，此时默认指向置空，前台在下次有效更新时进入静默空态；不为了保持“必须有歌”阻止运营清空列表。隐藏仍需维护默认指向一致性，这不是额外的删除审批。

### 11.5 隐藏（下架）、手动删除与低负担更新【Q04 修订】

#### 11.5.1 隐藏的含义

“隐藏”与“下架”是同一个业务动作，后台界面建议使用“隐藏”，不创建两个独立状态。服务器保存隐藏状态，**公开歌单不再返回该曲目**；不是仅用前端 CSS 隐藏一行。

隐藏只改变前台的可见/可选资格，不删除后台记录或音频文件，不要求向所有已打开页面发通知或强制立即停播。后台仍能查看、试听、重新启用。

新客户端或完成有效校验的客户端不再选用该曲；仍持有旧缓存且没有触发更新的页面，可能暂时继续播放。这是为降低实时同步成本接受的边界，不承诺几秒内全员生效。隐藏不是对音频 URL 的即时访问撤销。

#### 11.5.2 更新策略：事件触发，短时缓存复用，不做周期轮询

**取消 V1.0 的活跃播放定时校验。** 页面仅持续停留、后台仅进行隐藏操作，都不会触发新的前台定时请求。不为此新建或订阅歌单 SSE/WebSocket 推送。

| 触发时机 | 本机歌单仍在有效期 | 无缓存或缓存已过期 |
|---|---|---|
| 首次初始化/站内新页面初始化，且有启动或续播需要 | 复用同会话缓存 | 获取公共歌单 |
| 页面从后台恢复，且需要续播 | 复用缓存，按播放条件恢复 | 校验歌单，再按有效曲目恢复 |
| 用户打开主页音乐面板 | 先展示缓存，不重复请求 | 获取歌单并更新列表 |
| 用户明确播放、选曲或按下一首 | 用缓存完成合法性判断 | 校验后操作；等待中保留真实加载状态 |
| 当前曲目自然结束，准备下一首/单首重播 | 按缓存顺序播放 | 校验再选下一首；单首循环也经过此判断 |
| 音频出现 404/失效等资源错误 | 允许跳过复用期强制校验一次 | 校验后回退；同一故障链不反复刷新 |

**缓存复用期建议：5 分钟。** 这是“事件发生时，是否需要请求”的判断条件，**不是每 5 分钟自动发请求**。同源标签页内跨独立 HTML 跳转保留已校验歌单、版本和校验时间，避免每个页面重复冷启动请求。首次无缓存则正常请求一次。

同一页面并发出现初始化、打开面板、播放等动作时合并为一个在途请求；快速重复点击不重复拉取。页面隐藏、本次关闭、用户暂停时不为了续播主动检查；用户主动打开歌单/手动重试仍可请求。请求失败不清空最近有效歌单，自动失败重试要有限、退避，不把每次自然事件变成连续重试。

旧歌单失效后，只有下一次上述事件才检查；没有事件就没有请求，因此不设置“隐藏后 5 分钟内一定生效”的验收目标。用户长期不操作时，曲终也是自然更新机会。

**服务端实现建议：** 复用已有 Redis 缓存一份公共歌单及版本；后台启用、隐藏、排序、改名、默认变更或删除时失效/更新缓存。缓存访问失败允许有限回源，不每次请求都扫描完整音频元数据。无需增加新的缓存服务。[S16]

HTTP `ETag`/条件请求可用于减少未变化目录的响应体；`304` 仍是一笔请求，不能把它写成减少请求次数的保证。真正减少请求次数依靠“不轮询、复用有效缓存、合并请求”。是否接入条件请求由技术方案决定，不能让现有 JSON 响应封装误把无响应体的 `304` 当错误。[S17]

**负载解释：** 原 60 秒轮询的额外平均请求速率，在每个活跃页面每周期一次且均匀分布的假设下为 `活跃页面数 ÷ 60`。1,000 个活跃页面约为 16.7 次/秒，10,000 个约为 166.7 次/秒；这只是元数据轮询估算，不含音频 CDN 请求，不是容量测试，也不意味着服务器一定承受不了。V1 取消这部分与停留时长成正比的固定开销，实际请求量改由访问和操作事件决定，仍需上线前评估与限流。

#### 11.5.3 客户端发现当前曲目已隐藏

下一次有效校验发现当前曲目失效时：如果本次仍有播放意图且无阻断，则回退默认曲目，再回退有效列表第一首；没有有效曲目则停播并展示空态。用户本来暂停或关闭时只修正候选，不借机发声。

无需立即强制打断所有在线用户，也无需后台统计谁还在听。公共列表的新鲜度和资源错误兜底已经足够支撑首版日常运营。

#### 11.5.4 手动二次删除：点击时检查等待时间

```text
启用中
  → 管理员隐藏（从公开歌单移除，保留记录/音频）
  → 等待期经过（不触发自动任务）
  → 管理员再次点击“删除”，完成一次删除确认
  → 提交删除请求
  → 服务端在当次请求检查：当前仍为隐藏状态，且距最近一次隐藏已满等待期
  → 移除曲目管理记录/保留必要删除标识与操作日志，尝试删除发布音频
```

等待期建议沿用 **24 小时**，是运营容错初值，不是所有客户端缓存失效所需的保证时间。只在管理员发起删除时使用服务器时间判断，不需要后台计时器或周期扫描来“解锁”删除。等待期间展示“隐藏满 24 小时后可删除”与可删除时间即可，不需要每秒请求倒计时。

超过等待期后管理员可直接执行，不做在线人数判断、客户端确认、双人审批、回收站或另一个自动清理队列；仍沿用既有 Admin 权限和一次误操作确认。隐藏期间重新启用，则旧删除资格失效；再次隐藏后从最近一次隐藏时间重新计算。启用状态不能通过旧页面按钮或直接 API 删除。

删除请求须可安全重试。先保留最低限度的不可播放删除标识和对象路径，防止已删除曲目重新发布或丢失文件清理依据；当次 OSS 删除成功才显示文件删除成功。文件已不存在按完成处理；删除失败时仍不回到公开歌单，后台显示“文件删除失败，可重试”，由管理员手动重试，不需要专用定时重试服务。这些是一次删除的错误反馈，不增加独立管理模块。

从未启用的草稿或失败上传没有线上播放引用，建议允许直接清理，不套用保护已发布曲目的等待期；同样保留必要权限与错误处理。

#### 11.5.5 不承诺远程召回缓存

常规隐藏/删除不以 CDN 全网缓存刷新成功为前置条件，也不要求每次隐藏都调用 CDN 刷新。删除 OSS 文件不等于 CDN 或用户已下载的音频立即消失。确有紧急撤回需要时，由运维单独处理对应 CDN URL 的刷新；不将这条应急路径扩建为 V1 的审批或实时召回系统。[S12]

### 11.6 权限与审计【建议细化】

复用现有 Admin 身份和 observer 写操作总闸。建议 `super_admin`、`ops_admin` 管理 BGM，`observer` 只读；其他角色按现有权限表显式配置，不默认获得新写权限。新增菜单、接口和后台页面测试清单应同步。[S05]

上传、编辑、排序、启用、下架、默认切换、删除记录已有风格的后台操作日志。日志不包含密钥、用户 Token 或原始音频内容。后台操作日志不是本期放弃建设的“用户行为统计系统”。

## 12. 异常处理与并发约束

| 情形 | 建议处理 | 禁止行为 |
|---|---|---|
| 没有曲目/全部不可用 | 主页仍有 BGM 入口，打开显示“暂时没有可播放的背景音乐”；控制禁用；其他页无无效气泡 | 卡加载页、无限尝试默认 ID |
| 自动播放被阻止 | 留下静止的手动入口；状态真实 | 弹自制授权框冒充浏览器权限、每次触屏重试 |
| 歌单请求失败 | 可在合理范围内保留最近一次有效版本；本次无缓存则静默不可用，允许手动重试 | 清空正确缓存并声称后台全部下架 |
| 音频加载/播放失败 | 区分权限拦截和资源错误；自动播放路径跳过失败候选，每首在一轮内最多一次；全失败后停止 | 默认失败→下一首→默认的无限循环 |
| 弱网缓冲 | 显示轻加载/静止，不覆盖用户意图；可暂停/关闭 | 唱片正常转却长期没声音 |
| 快速连续切歌 | 最后操作有效，旧异步结果失效；不重叠输出 | 第一首迟到覆盖最后一首 |
| 关闭后旧曲加载成功 | 丢弃旧启动动作 | 关闭后重新出声 |
| 退出/切账号 | 取消旧身份同步；保护缓存隔离；音乐本身按本次公共状态处理 | 把 A 的操作写入 B |
| 偏好保存失败 | 本机即时生效并保留待同步；弱提示一次 | 为保存音量反复弹窗或阻止播放 |
| 浏览器本机存储不可用 | 本页内存模式继续；跨页恢复不可保证，静默回到安全状态 | 因存储异常让主页报错 |
| 删除文件/旧 URL 失效 | 资源错误链最多强制校验一次目录后回退；OSS 删除失败在原管理页提示手动重试 | 重用已删除 ID、错误链无限拉目录、显示虚假删除成功 |
| 特殊字符/超长名称 | 安全转义、长度校验、固定容器展示 | 直接拼接可执行 HTML |

网络重试、超时、缓存复用与删除等待参数见下一节，均应有限、有去重。缓存到期不主动发请求；不能在用户关闭后继续无意义加载。

### 13.1 参数建议（不是已确认体验数值）

| 参数 | 建议初值 | 说明 |

## 15. 埋点、上线与后续交付

### 15.1 事件定义【已确认不新建管线】

预留 `bgm_auto_play_success`、`bgm_auto_play_fail`、`bgm_sheet_open`、`bgm_track_change`、`bgm_pause`、`bgm_resume`、`bgm_close_session`。
