### [RP-002] 语音长期记忆抽取的配置、事实归属与长期价值（待评估）

- **涉及入口**：后台 `voice_call_script.memory.prompt_template`、逐轮 `VOICE-MEM-01` 提取、`voice_memory_job`、`voice_memory_trace` 与用户级向量记忆。不改变文字聊天 Step6 的独立链路。
- **用户场景**：一通语音结束后，用户希望后续对话记得自己明确说过且有长期价值的事实或约定；不希望助手临场编出的共同经历、尚未确认的猜测、当次情绪或道别，被当成确定的长期记忆。
- **观察依据**：2026-09-28 本地样本的语音记忆超时修复后，14 个原失败任务补跑，11 个成功、3 个跳过，形成 17 条向量文档。逐轮核对发现：部分 `user` 记忆的具体事实只出现在助手回复，用户未确认且后续曾质疑；有的“不确定印象”被写成确定经历；一次性睡觉、亲昵互动和道别也进入长期记忆。此处只记录问题类别及数量，不保存账号、通话 ID、私人转写或向量正文。提取能完成与记忆内容可信是两个独立验收点。
- **当前实现**：提取 Prompt 由代码内固定 `MEMORY_RULES`、后台可编辑的 `memory.prompt_template` 和回合输入拼接。该字段已有草稿、校验、发布入口；上述本地样本核对时，默认值、已发布语音话术 V1 及样本通话快照中的该字段均为空，因此使用内置规则。现有输出校验主要约束 JSON、`memory_type`、Stable Key、长度和条数，不能确认事实由谁说出、是否已被用户确认或是否值得长期保留。
- **快照与重试边界**：通话建立时冻结后台话术配置，后续发布不会追溯改写旧通话的 `memory.prompt_template`；固定 `MEMORY_RULES` 由执行提取时的服务代码提供。已保存首次提取候选的重试复用候选，不重新抽取。没有可确认的已播放助手文本时，当前回合在入队资格判断中跳过，用户在该回合的纠正可能未参与记忆处理。

#### 2026-09-28 当前实现补记

- 内置记忆提示词已参照文字链路的写法和示例调整，采用「作息-惯性-熬夜」等中文三层 key 示例，并说明同主题合并、独立主题拆分及纠正保留原意。输出仍为 `memory_items` 数组及 `memory_type`、`stable_key`、`content` 三个字段；共享校验继续要求三段 key、长度和条数上限，没有新增「只能中文」的限制。
- 后台已新增「语音通话 → 语音 Prompt」只读页，记忆抽取 Tab 可查阅当前服务代码的固定规则、拼装模板、输入输出及来源。配置段和通话数据显示为占位符；该页没有读取某通话实际生效完整提示词的能力，也未提供新的配置、发布或回退入口。
- 上述为 R01 修复前的实现补记，主要补充规则可读性和模板展示；后续事实质量规则及定向数据处理的进展见下节。

#### 候选需求

1. **明确提示词配置边界**：保留不可被后台覆盖的安全、隐私、可写记忆路和输出格式约束；将事实归属、不确定性、纠正和长期价值等业务抽取规则形成可审查的版本化配置。后台应能看见当前实际生效的完整提示词及其来源，明确空自定义字段时使用的规则，并支持草稿校验、发布与回退。是否要求非空业务默认模板，需在评审时定稿。
2. **事实必须有可核对来源**：`user` 记忆只能来自用户最终转写中的明确陈述或用户已确认的事实，不能把助手的提问、猜测、回忆性话术或“你曾说过”直接归属给用户。`character_private` 也只能记录有根据且有持续价值的角色私有事实或明确约定；助手当次的语气和表演性动作，不自动成为长期事实。无充分依据时输出空记忆。
3. **保留不确定性与纠正**：用户使用“好像、可能、记不清”、否定或更正时，记忆不得升级为确定结论。后续回合质疑或纠正先前内容时，应避免继续固化相反的旧候选；如何处理没有已播放助手文本的用户纠正，需要单独确定可靠的输入与闭环条件，不能凭未播放内容补造依据。
4. **控制长期价值**：单次睡觉、道别、临场情绪、一次互动请求及已完成动作，默认不推断为稳定偏好、角色规则或长期约定；只有用户明确表达持续偏好，或双方明确形成可后续使用的约定，才考虑写入。是否保留短期上下文由本通缓冲承担，不用长期向量记忆替代。
5. **使结果可验收**：验收时应能将每条候选对应到允许使用的原话来源，并区分“提取为空”“候选因格式/安全/来源/价值被丢弃”和“外部写入失败”。来源记录、抽取输出留存和脱敏方式须符合现有转写保留期、删除围栏与隐私规则；本条不预设新增持久化字段。

#### 验收场景草案

| 场景 | 期望 |
|---|---|
| 助手声称双方曾共同去过某地，用户只是询问或表示怀疑 | 不写成确定的 `user` 经历；助手单方面说法也不得冒充已确认约定。 |
| 用户说“好像是夏天”，随后说“可能记错了” | 保留不确定性与后续纠正，不生成互相矛盾的确定记忆。 |
| 用户说要睡觉、拜拜，或仅在本次互动中提出亲昵要求 | 不推断为稳定日程、长期偏好或角色行为规则。 |
| 用户明确表达持续偏好或双方明确约定以后继续某事 | 在来源、类型和安全条件都满足时，输出可追溯的语义原子并完成写入。 |
| 用户提出纠正，但该回合没有可确认已播放的助手文本 | 明确此纠正的处理路径和任务状态；不使用未播放的助手生成内容。 |
| 发布新的抽取话术后，分别处理新通话和旧通话补跑 | 新通话使用新版本快照；旧通话仍按其原快照处理，后台能展示这一差异。 |
