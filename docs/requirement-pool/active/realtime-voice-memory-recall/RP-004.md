### [RP-004] 语音实时召回与会前加载使用新的记忆检索能力

**本期决定**：用户在记忆存入与分路混合召回优化 PRD v2（本地留存，未随本次提交；原引用：`../../../design/memory-retrieval/history/PRD-记忆存入与分路混合召回优化-v2.md`）的需求确认中选择 B，并明确“语音的召回不在本期范围，可以记录一个需求作为下个版本的工作内容”。语音实时召回和会前记忆加载的算法升级均移至下一版本；本期仍包含语音写入维护 BM25 索引的必要配套。本条对应确认台账 RQ-03、RQ-04。

**当前实现与影响**：实时召回优先使用通话短期内容和缓存，需要查询长期记忆时，以一个改写 query 查询四类向量记忆；会前加载查询 `user`、`character_private` 两类，并由下游按相关性、质量和时间等元数据筛选。文字检索升级并不会自动升级这两个语音入口。依据：[实时召回](../../../../backend/services/realtime_voice_recall_service.py)、[会前记忆来源](../../../../backend/services/realtime_voice_context_source_service.py)、[会前选择](../../../../backend/services/realtime_voice_context_pack_service.py)。上述为静态实现事实，未核验线上效果。

**下一版本工作内容**：分别评审实时召回和会前加载如何使用新的记忆检索能力。可评估复用本期向量与 BM25 召回、rerank 的底层能力；语音继续以自身输入和业务场景为依据，具体算法、排序、数量及预算规则需在下一版本定稿。

**待细化事项**：两个入口各自的查询词组来源、分类过滤、候选与最终数量、排序和相关性门槛；模型调用的时间预算、失败降级、缓存与迟到结果处理；后台配置、诊断和质量评测。会前加载还需核对可信时间等元数据的可用性及过滤口径，不能以索引或回填时间冒充记忆时间。

**验收场景草案**：

- 通话中询问现有长期记忆时，分别观察候选命中和实际投递，区分短期内容、缓存和长期检索来源。
- 向量、BM25 或 rerank 故障以及结果迟到时，按定稿规则降级，验证语音播放和投递行为。
- 会前加载分别验证有效、缺少可信时间、过期和已删除的候选，说明最终是否注入及原因。
- 验证私有记忆的用户隔离，并在固定样本上比较旧新召回效果、时延和成本。

**恢复位置与边界**：下一版本需求细化时，从两个读取入口及其下游选择分别开始，并核对本期最终落地的检索、索引和配置契约。语音内容抽取质量沿 [RP-002](../realtime-voice-memory-extraction/RP-002.md)另行处理。本条记录不授权业务开发、部署或生产数据操作。
