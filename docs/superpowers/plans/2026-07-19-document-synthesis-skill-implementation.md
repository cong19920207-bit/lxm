# “文档归纳”全局 Skill 实施计划

## 目标

以本项目当前 `docs/` 的目录组织、权威入口和文档格式为参考，创建可跨项目使用的全局 Skill `document-synthesis`（展示名“文档归纳”）。Skill 帮助 Codex 盘点、整理和补齐理解项目所需的文档，同时保留既有文档，不读取业务代码补事实。

## 实施范围

1. 提炼本项目的通用文档结构：索引、机器路由、产品设计、契约、进度、测试、技术债、版本和归档。
2. 提炼主要文档格式：PRD、开发步骤、实施计划、进度、契约、技术债、审查、测试清单和测试报告。
3. 编写简洁 Skill 工作流：先盘点和给方案，用户确认后整理；原文保留或归档；缺失内容标记待补充，不猜测。
4. 新项目可直接采用推荐结构；旧项目优先映射现有路径，逐步收敛，不强制一次迁移。
5. 使用模板帮助其他项目补齐缺少的文档，但只创建实际需要的类型。
6. 运行 Skill 结构校验和跨项目场景测试后，安装到 Codex 用户级全局 skills 目录。

## Skill 组成

```text
document-synthesis/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── docs-structure.md
│   └── document-formats.md
└── assets/templates/
```

模板覆盖：`INDEX.md`、`llm-manifest.json`、项目概览、PRD、开发步骤、实施计划、进度、契约、技术债、审查、测试清单、测试报告和版本记录。

## 验收

- 能根据已有 `docs/` 判断哪些文档已存在、缺失或重复。
- 能说明每类文档用于理解项目的什么部分，并按本项目风格生成栏目。
- 未经确认不修改目标项目文档。
- 不读取业务代码补文档事实。
- 不物理删除既有文档；被替代内容保留在 history/archive 或写入前快照。
- 日常读取优先使用 `INDEX.md`、manifest 和当前权威文档，默认排除草案、历史、归档和快照。
- Skill 通过格式校验和至少三个跨项目使用场景测试。
