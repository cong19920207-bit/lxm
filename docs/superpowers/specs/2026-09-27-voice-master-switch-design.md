# 语音通话独立总开关设计

状态：设计稿，待书面审阅。日期：2026-09-27。

## 目标与验收

语音通话总开关拥有独立页面、独立持久化状态和独立发布请求。管理员点击开关后看到一次确认弹窗；确认后由一次请求完成保存与生效。页面只在服务端确认成功并重新读取生效状态后改变开关显示。取消、冲突或失败均保持原显示并给出原因。

总开关请求不得保存、校验、发布、丢弃或重设 `voice_call_config`、`voice_call_script` 及其草稿。反向约束也成立：普通语音配置的保存、发布和回滚不得改变独立总开关。总开关只控制新通话准入，已建立通话不因切换而中断。维护模式、软停、灰度名单、额度及能力门禁仍按原规则执行；开启总开关不绕过它们。

## 当前原因与方案选择

现有开关在 `admin/pages/voice-config.html` 中修改 `voice_call_config.global.enabled`。保存只写 `global` 草稿，但后续发布会发布整份配置草稿。直接把原开关移到新页面，或提供一个仅改现有 active 整包的接口，仍会影响配置版本、待发布草稿及回滚语义。

采用独立配置键 `voice_call_master_switch`。它只包含布尔 `enabled`，使用既有 `admin_config` 表的 active 版本记录，不设草稿；独立接口一次完成确认与发布。运行时在原有两份语音配置之外读取该键，将其作为总准入门禁。相比直接修改 `voice_call_config` active 整包，此方案不改变其版本、摘要、草稿修订号或发布历史。

## 数据与迁移

- 新键：`voice_call_master_switch`；配置值精确为 `{"enabled": boolean}`，版本从 1 开始。使用现有 `admin_config` 字段，不新增表列。
- 部署数据迁移仅插入这个键的首个 active 版本，不修改任何既有 active 配置、草稿或历史。初值来自迁移时的 `voice_call_config` 生效版 `global.enabled`；缺失、无效或不可判定时设为关闭，并记录迁移结果。
- 新运行时代码上线前先完成迁移；上线后该键缺失、损坏或读取失败时禁止新通话并在管理页显示“状态不可用”，不从旧草稿推断状态。
- 旧 `voice_call_config.global.enabled` 保留在已有整包结构及历史中以兼容既有 schema，但不再决定总启停。旧配置页不显示原开关；全局 JSON 编辑区不提供该字段的修改入口，服务端拒绝新的草稿保存请求改变该字段。历史版本或迁移前遗留草稿中的值即使不同，普通发布及回滚也不回写独立键。

## 接口、权限与审计

- `GET /api/admin/voice/master-switch`：返回生效布尔值、版本、更新时间和操作人；沿用语音配置的只读角色集合。
- `POST /api/admin/voice/master-switch/publish`：请求体精确包含目标 `enabled` 与页面读取的 `expected_version`。沿用原开关的写权限：`super_admin`、`tech_ops`。服务端在事务中锁定独立键并核对版本，成功时只新增该键的 active 版本、写操作日志并提交；并发版本变化返回 409。
- 确认弹窗显示“当前状态 → 目标状态”和对新通话的影响，只有“取消 / 确认开启（或关闭）”两个操作，不要求额外的草稿保存、校验、发布点击或输入 `CONFIRM`。服务端记录管理员、时间、前后状态、版本和请求来源；取消不请求写接口。
- 开启时只读核验当前**已生效**语音配置具备运行所需的可信结构和必需前置条件。核验失败则拒绝开启并展示具体可处理的原因；关闭不依赖其他配置草稿或待发布状态。核验不写入、发布或丢弃其他配置。
- 重复请求与响应丢失：重复请求若版本已变化，返回冲突；页面重新读取生效状态，显示服务端实际值。页面不得凭前端请求成功推测生效状态。

## 页面与交互

在“语音通话”二级菜单新增“总开关”页面，专门显示当前生效状态、开关、最后操作信息和本次操作错误。只读角色可查看，开关禁用。移除“语音设置”页的总开关卡片及对应脚本事件；该页保留其他分区的编辑、草稿、校验、发布和回滚功能。

交互顺序：读取生效状态 → 点击拟切换方向 → 立即把视觉开关保持在原状态并打开确认弹窗 → 确认后禁用重复操作并发请求 → 服务端保存且生效 → 重新 GET 核对 → 更新视觉开关。失败、冲突或取消时保持当前生效状态，错误放在开关旁；冲突时提示刷新后的状态。

## 运行时边界

语音创建链路读取独立开关的 active 状态。关闭时直接拒绝新通话；开启时继续执行原有维护、软停、灰度、额度、能力及 Provider 检查。技术回退使用可信已发布门禁中的其他字段，但其旧 `global.enabled` 不再覆盖独立开关。独立开关状态无法可信读取时按关闭处理。

新通话快照额外记录开关版本及生效值，供事后解释准入决定；不改写原 `resolved_config` 及其已发布摘要。`voice_call_config` 的普通发布和回滚不触碰独立键。既有软停操作仍只修改 `global.soft_stop`；总开关开启不能解除软停。

## 验证与交付

1. 浏览器：确认、取消、失败、重复点击、并发冲突、只读角色，以及旧配置页不再出现开关；成功前视觉状态不变。
2. 接口与数据：新请求只改变独立键和对应审计；`voice_call_config` 的 active 版本、草稿内容及修订号在切换前后完全一致；普通配置发布和回滚不影响开关。
3. 运行时：关闭阻断新通话，开启仍受维护、软停和灰度限制；已建立通话不中断；独立状态缺失或不可用时禁止新通话；快照记录实际开关版本。
4. 迁移：分别覆盖原先开启、关闭、缺失和无效状态；保留现有草稿，且不产生额外配置发布。
5. 本地 Docker：迁移、后端重建、页面和接口冒烟测试；不通过测试主动开启真实语音服务。

主要风险在运行时门禁与迁移的交界：若迁移未执行或独立状态不可用，新通话会被拒绝。部署顺序必须先迁移、再切换运行时读取；回退应用版本时保留独立键，旧版本仍按旧 `global.enabled` 工作，回退前需确认旧值对应的准入状态。
