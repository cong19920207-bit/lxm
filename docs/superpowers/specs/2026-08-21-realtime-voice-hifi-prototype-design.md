# 林小梦实时语音通话高保真 H5 原型设计

日期：2026-08-21

状态：方案已确认，待规格复核

目标设备：iPhone 16 Pro（CSS 视口 402 × 874），同时适配其他现代移动端视口

## 1. 目的

将现有逐态评审 Demo 升级为符合当前 LXM H5 工程结构的高保真、可交互产品页面。交付物应能作为正式前端开发基线，而不是带手机机框、假状态栏和调试面板的演示画布。

本设计以以下内容为约束：

- `docs/design/realtime_voice/P1/PRD-LXM语音通话仿真交互设计-v2.md`；
- `frontend/pages/index.html` 的首页快捷入口与登录策略；
- `frontend/pages/chat.html` 的沉浸式全屏语言；
- `frontend/static/css/common.css`、`h5-theme.css` 的基础变量、安全区和无障碍约定；
- `backend/main.py` 对 `frontend/pages/*.html` 的通用页面路由。

## 2. 现状结论

### 2.1 当前工程边界

项目是 FastAPI 托管的原生 HTML/CSS/JavaScript H5，不是 React、Vue 或原生 iOS 工程。正式页面直接占满浏览器视口，并通过 `env(safe-area-inset-*)` 避让系统区域。

首页“语音通话”当前仍执行“敬请期待”；正式语音页面、前端音频会话实现和完整生产语音 Router 尚不存在。现有 `docs/design/realtime_voice/P1/demo/demo-voice-call-states.html` 是状态评审器，不是产品页面。

### 2.2 现有 Demo 的主要问题

1. 固定 402 × 874 内容被包在额外手机机框中，桌面评审结构侵入产品结构。
2. 自绘灵动岛、时间、电量和信号，与真机系统 UI 重复。
3. 状态导航、变体 Chips 和说明面板属于调试工具，不应出现在产品画面。
4. 十二套 Scene 重复完整 DOM，难以映射真实事件、维护持续控件状态和复用动效。
5. “扬声器”被假设为始终可切换，但 Web 音频输出能力取决于安全上下文、权限和浏览器支持。
6. Demo 的结束页与聊天流卡片是孤立画面，没有形成真实导航和异步摘要更新关系。

## 3. 设计目标与非目标

### 3.1 目标

- 产出无设备机框、无假系统 UI、无可见调试控件的正式 H5 页面。
- 完整覆盖 PRD 的权限、呼叫、连接、通话三阶段、重连、未接、技术失败和结束状态。
- 让状态、控件、文案和动效通过单一状态机驱动。
- 让 MockAdapter 与未来 ProviderAdapter 使用同一 UI 事件契约。
- 从首页进入，并能返回聊天页验证通话记录卡片。
- 在 402 × 874 上达到高保真，并能适配窄屏、长屏和横屏安全退化。
- 遵守触控尺寸、对比度、屏幕阅读器和减少动态偏好。

### 3.2 非目标

- 本次不实现真实 S2S、WebSocket、计费、CALL-01、转写、记忆或后处理服务。
- 不在聊天页增加第二个通话发起入口。
- 不公开显示实时字幕或内部转写。
- 不实现原生 CallKit、后台持续通话或锁屏通话。
- 不用前端原型替代 PRD 中仍需后端确认的计费、保留期和删除级联决策。

## 4. 选定架构

采用“正式 H5 产品界面 + 可替换通话适配器”。

```text
index.html / 语音通话
          ↓
voice-call.html
  ├─ VoiceCallView：渲染与可访问性
  ├─ VoiceCallController：状态机与用户操作
  ├─ MockVoiceCallAdapter：原型事件与场景复现
  └─ VoiceCallAdapter 接口：未来接业务 API / Provider
          ↓
chat.html / source=call 通话记录卡片
```

### 4.1 文件边界

正式实现阶段预期涉及：

- `frontend/pages/voice-call.html`：语义化页面骨架；
- `frontend/static/css/voice-call.css`：页面视觉、状态样式和动效；
- `frontend/static/js/voice-call.js`：状态机、控制器、视图更新和能力检测；
- `frontend/static/js/voice-call-mock.js`：仅用于原型的确定性场景适配器；
- `frontend/pages/index.html`：登录通过后进入语音页面；
- `frontend/pages/chat.html`：增加 `source=call` 的独立卡片渲染分支；
- 对应静态契约测试和浏览器交互测试。

页面继续复用 `/static/css/common.css`、`/static/css/h5-theme.css` 和 `/static/js/api.js`。`body.voice-call-immersive` 对通用 neo 卡片规则做页面级隔离，方式与 `chat-immersive` 一致。

### 4.2 原型与生产的边界

MockAdapter 只负责产生确定性的事件序列，不拥有任何产品 DOM。生产接入时替换 Adapter，不重写 UI 和状态机。

原型场景通过 URL 参数选择，例如：

```text
/pages/voice-call.html?prototype=1&scenario=answered
/pages/voice-call.html?prototype=1&scenario=missed
/pages/voice-call.html?prototype=1&scenario=reconnect
/pages/voice-call.html?prototype=1&scenario=failed
/pages/voice-call.html?prototype=1&scenario=no-quota
```

参数和测试钩子不渲染成界面。非原型模式未接入真实 Adapter 时必须明确阻断，不能自动播放一场模拟通话。

本次高保真交付处于原型阶段：首页已登录入口明确跳转到
`/pages/voice-call.html?prototype=1&scenario=answered`。生产语音 Adapter 接入并通过验收后，入口才改为无原型参数的正式地址；不得把 MockAdapter 当作线上语音能力发布。

## 5. 视口与布局

### 5.1 页面坐标系

- `html, body` 使用真实浏览器宽高；主容器使用 `100dvh`，回退为 `100vh`。
- `viewport` 包含 `viewport-fit=cover`。
- 顶部内容以 `env(safe-area-inset-top)` 为起点；底部控制区包含 `env(safe-area-inset-bottom)`。
- 不设 402px 固定宽度、不设圆角屏幕裁切、不绘制设备外壳。
- 桌面打开时仍呈现全视口产品页面；不增加居中手机模型。

### 5.2 纵向分区

1. 顶部状态区：安全区之后显示状态、通话计时或低额度提醒。
2. 人物舞台：全屏竖版角色图为主视觉，状态光效围绕头肩与环境变化。
3. 状态反馈区：一句主状态，必要时一行辅助说明；不显示字幕。
4. 控制区：通话中为静音、挂断、声音三个操作；阻断和终态使用专用行动区。

小高度设备优先压缩人物舞台和区块间距，不缩小核心按钮触控区。横屏显示可用的简化布局，并提示竖屏体验更佳，但不强制旋转或阻断挂断。

## 6. 视觉系统

### 6.1 方向

沿用首页与聊天页实际使用的“深色人物沉浸 + 紫蓝高透玻璃”，不沿用早期文档中的粗黑漫画边框。

- 背景优先复用 `frontend/static/images/Index/Index.png` 和现有竖版情绪资产。
- 色彩基底为午夜蓝黑、低饱和紫和角色图片本身的暖光。
- 文本使用系统字体，数字启用等宽数字特性。
- 玻璃只用于需要触控或承载信息的区域，不给整屏套厚重底板。
- 红色只用于挂断和不可恢复的危险反馈。

### 6.2 信息层级

- 一级：人物与当前通话关系状态。
- 二级：通话状态、计时和用户下一步可执行操作。
- 三级：连接说明、打断提示、摘要整理状态等短暂反馈。

主状态文案保持口语化，技术细节只在明确失败页出现。未接代表“她此刻不方便”；Provider 失败代表“系统暂时无法接通”，两者的图形、标题和统计语义必须不同。

## 7. 页面状态

UI 使用一个持久页面壳，根据状态更新文案、视觉变量、可用控件和可访问性播报。

| UI 状态 | 主文案 | 视觉 | 操作 |
|---|---|---|---|
| `permission` | 允许麦克风后才能和她通话 | 清晰人物 + 低位权限 Sheet | 允许麦克风、返回 |
| `preflight` | 正在准备这通电话 | 轻微环境呼吸，不显示机械百分比 | 取消 |
| `calling` | 正在呼叫林小梦… | 人物轻虚化 + 三层柔和扩散波纹 | 挂断 |
| `connecting` | 她快接到了… | 波纹收束，人物逐渐清晰 | 挂断 |
| `listening` | 林小梦在听 | 冷紫微光随本地输入音量轻动 | 静音、声音、挂断 |
| `thinking` | 林小梦想一下 | 动效放慢，光点短暂内聚 | 静音、声音、挂断 |
| `speaking` | 林小梦正在说 | 暖色呼吸光 + 非字幕型语音节奏 | 静音、声音、挂断；开口打断 |
| `reconnecting` | 网络有点不稳，正在重新连接 | 去饱和、压暗、柔和重连指示 | 挂断 |
| `missed` | 她现在可能不方便 | 保留人物环境，不使用错误图标 | 返回聊天、稍后再试 |
| `failed` | 暂时无法接通 | 克制的技术失败反馈 | 稍后再试、返回聊天 |
| `ending` | 正在结束通话 | 控件锁定，短暂淡出 | 无重复操作 |
| `ended` | 这次聊了 05:32 | 通话结果层 + 记录整理状态 | 返回聊天 |

### 7.1 前置阻断变体

以下场景复用同一 `blocked` Sheet 组件，但必须使用不同文案和行动：

- 麦克风被拒绝：说明如何到浏览器设置开启；
- 浏览器不支持：说明换用受支持环境，不创建通话；
- 无剩余时长：展示剩余时间为零和当前可用处理方式；
- 另一设备通话中：说明同一账号一次只能接通一台；
- 服务维护或容量已满：提示稍后重试；
- 音频输出切换不受支持：不伪造开关状态，说明由系统控制。

## 8. 核心交互

### 8.1 从首页发起

1. 未登录沿用共享登录弹窗；登录成功只进入语音页一次。
2. 已登录进入 `/pages/voice-call.html`。
3. 首次或权限状态未知时显示权限说明，由用户点击触发 `getUserMedia`。
4. 权限已授予时进入 `preflight`；只有检查通过才进入角色接听决策。

权限请求必须由明确的用户操作触发。页面不能在无说明的加载阶段偷偷请求麦克风。

### 8.2 通话控制

- 静音：即时更新图标、标签和 `aria-pressed`；静音后不再运行用户静音超时逻辑。
- 挂断：首次点击立即进入 `ending` 并禁用重复点击；只产生一次结束意图。
- 声音：先检测输出选择能力。支持时调用 Adapter；不支持时打开说明 Sheet，不能只改变按钮颜色。
- 页面离开：在有效通话中拦截误触返回，显示“结束并离开 / 继续通话”；浏览器强制关闭由服务端心跳兜底。

### 8.3 自然打断

`speaking` 状态持续监听经过回声抑制后的本地输入能量。短促附和只产生轻微视觉响应；超过 Adapter 配置阈值后：

1. 立即停止当前远端播放；
2. UI 在一个动画周期内切换到 `listening`；
3. 不弹“打断成功”Toast；
4. 将打断事件交给 Adapter 闭环当前回合。

首次进入 `speaking` 时可短暂显示“直接开口就能打断她”，同一用户后续通话不反复教学。

### 8.4 静音与软收尾

- 只有 `listening` 且麦克风未静音、设备正常时才运行 6 秒确认和 12 秒告别逻辑。
- 剩余时长达到阈值时只显示柔和提示并由 Adapter 注入 `time_low`；不弹阻断弹窗。
- 额度为零后进入自然收尾，前端不显示负余额，也不自行决定账本口径。

## 9. 动效设计

### 9.1 动效原则

动效表达“她的状态”，不表达模型流水线。避免百分比加载、扫描线、信号强度和高频科技粒子。

| 动效 | 建议时长/节奏 | 用途 |
|---|---|---|
| 页面入场 | 320ms | 背景与主要信息淡入 |
| 普通状态切换 | 180–260ms | 文案、光效和控件状态 |
| 呼叫波纹 | 2.4–2.8s 循环 | 正在呼叫 |
| 连接收束 | 420ms | 呼叫转连接 |
| 倾听响应 | 80–140ms 平滑采样 | 映射用户音量，不直接画录音波形 |
| 思考内聚 | 1.6s 低频循环 | 等待模型响应 |
| 说话呼吸 | 0.8–1.4s 随播放能量 | 表达声音节奏 |
| 重连去饱和 | 240ms 进入，320ms 恢复 | 明确连接中断与恢复 |
| 结束退场 | 240ms + 结果层 320ms | 防止突然跳页 |

所有循环动画必须在页面隐藏、终态和 `prefers-reduced-motion: reduce` 下停止。减少动态模式保留状态颜色和文案变化，不依赖运动传达必要信息。

## 10. Adapter 事件契约

UI 只消费业务语义事件，不直接读取 Provider 私有事件。

```js
adapter.on('state', { state, reason })
adapter.on('turn', { phase: 'listening' | 'thinking' | 'speaking' })
adapter.on('duration', { elapsedSeconds, remainingSeconds })
adapter.on('input-level', { normalizedLevel })
adapter.on('output-level', { normalizedLevel })
adapter.on('reconnect', { attempt, maxAttempts })
adapter.on('ended', { status, durationSeconds, summaryStatus })
adapter.on('error', { code, retryable })
```

Controller 对外只发出意图：

```js
adapter.start()
adapter.setMuted(boolean)
adapter.requestOutputRoute()
adapter.interrupt()
adapter.hangup(reason)
adapter.retry()
adapter.destroy()
```

重复、过期或与当前状态不相容的事件由 Controller 丢弃。`ending` 和 `ended` 是幂等终态；重复挂断不能触发第二次导航或第二次结果写入。

## 11. 通话记录卡片

聊天时间线遇到 `source=call` 时渲染独立卡片，不伪装成 AI 气泡。

卡片结构：

- 电话图标与“语音通话”；
- 完成、未接或异常结束状态；
- 通话时长；
- 摘要区；
- 发生时间沿用聊天时间线分隔规则。

摘要状态：

- `pending`：显示“正在整理这次通话…”及静态占位，不使用无限旋转 Spinner；
- `ready`：显示一至两行短摘要；
- `failed`：显示“通话记录已保存，摘要暂时没有生成”，不把整张卡标红。

高保真原型通过明确的 URL fixture 参数展示三种状态，例如
`/pages/chat.html?prototype_call_card=pending`。通话结束后的原型导航携带该参数，便于跨页面验证；生产代码只接受时间线 `source=call` 数据，不能依赖 URL 或 `sessionStorage` 生成记录。

## 12. 异常与恢复

- 明确网络断开立即进入 `reconnecting`；重连期间冻结计时展示，不显示用户时长继续减少。
- 重连成功回到断开前的通话阶段，并使用短暂“已重新连接”可访问性播报。
- 重连超时进入异常结束，不进入“她没接”的未接页。
- CALL-01 未接、用户主动挂断、静音结束、额度结束、技术失败使用不同结果状态。
- 页面重新进入时，原型模式从初始状态开始；生产模式应通过 `call_id` 查询恢复，原型不伪造恢复能力。

## 13. 隐私与无障碍

### 13.1 隐私表达

首次权限说明明确：

- 麦克风只在通话中使用；
- 会保存通话文字记录和摘要；
- 原型与建议默认策略不保存原始音频；若生产策略改变，必须在上线前同步产品文案和授权流程。

通话页不展示后台转写、记忆推理或内部 Prompt 信息。

### 13.2 无障碍

- 核心触控区不小于 44 × 44pt，主要通话按钮建议 64pt。
- 控件提供明确中文 `aria-label`、`aria-pressed` 和禁用原因。
- 状态变化使用节制的 `aria-live`；音量采样和每秒计时不连续播报。
- 状态不能只依赖颜色；静音、重连和失败同时具备图标、标签与文案。
- 正文与背景达到 WCAG AA 对比度；在复杂人物背景后增加局部遮罩。
- 支持 VoiceOver 顺序：状态 → 计时 → 辅助说明 → 操作。

## 14. 验收标准

### 14.1 视觉

- 402 × 874 截图中无机框、假灵动岛、假状态栏和调试控件。
- 页面没有横向滚动，底部控件不侵入 Home Indicator 安全区。
- 关键文案、人物面部和挂断按钮在所有主状态下层级清晰。
- 390 × 844、393 × 852、402 × 874、430 × 932 视口无裁切。
- 320px 宽和横屏可以完成授权、挂断和返回，不要求保持完整艺术构图。

### 14.2 交互

- 首页访客点击先弹共享登录，成功后只进入一次语音页。
- 授权、拒绝、无额度、占用、未接、接通、重连、失败和结束均可确定性复现。
- 静音和声音控件状态跨 `listening/thinking/speaking` 保持一致。
- 挂断、结束和返回不会重复触发。
- `speaking` 中持续输入能触发自然打断，短促输入不误触发。
- 返回聊天后可验证通话记录卡片的 pending、ready 和 failed 摘要状态。

### 14.3 技术质量

- 无控制台错误、无图片 404、无未处理 Promise rejection。
- 页面所有可交互元素可用键盘和屏幕阅读器访问。
- `prefers-reduced-motion` 下无无限循环动画。
- MockAdapter 使用 fake timers 或确定性时钟，测试不依赖真实等待。
- 静态契约测试验证页面入口、状态枚举、文案、无设备壳结构和聊天卡片分支。

## 15. 建议但不自动扩展的后续需求

以下能力有产品价值，但不作为本次高保真原型的默认扩展：

1. 蓝牙耳机连接、断开和音频输出变化的可见反馈；
2. 来电、闹钟、锁屏、切后台导致的音频中断处理；
3. 用户可查看、更正或删除语音产生的长期记忆；
4. 通话文字记录的保留期和删除级联入口；
5. 原生壳或 Native Bridge 提供稳定音频路由和后台通话能力。

这些项目需要单独产品决策或底层能力，不应为了视觉完整而在本次原型中伪造。

## 16. 设计完成定义

本设计完成后，正式实现交付应同时包含：

- 无机框的高保真语音页面；
- 全主流程与异常流程的可交互原型；
- 首页入口和聊天流通话卡片；
- 可替换 Adapter 契约；
- iPhone 16 Pro 关键状态截图；
- 自动化静态契约与浏览器交互验证结果。

达到以上条件才可称为“可直接进入真实语音服务接入的高保真前端基线”。
