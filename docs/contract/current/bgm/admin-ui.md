STEP-003增加`admin/static/js/bgm-upload-admin.js`与右侧上传抽屉。支持拖入/选择音频、文件卡/移除、Unicode码点计数、真实阶段文字（不伪造百分比）。S/O可上传；失败行可重选文件并关联原曲目重试。输入按服务端同一Unicode码点与类型/体积边界检查，服务端仍负责真实解码。先在独立Admin localStorage键保存操作UUID与文件SHA256、规范化快照，再发请求；只保存元数据，最多保留50个待核对凭据，不存文件二进制、不访问H5偏好。无法可靠保存时明确不提交。刷新后可恢复原标识，重选同一文件继续接纳，或GET核对原结果。明确终态才清除待核对凭据。

超时/网络异常不当成已确认失败；401保留localStorage凭据后沿既有登录跳转，403就地显示权限中断。恢复不会自动生成第二条曲目。后端就绪结果明确显示尚未启用。

单个原生audio承担后台试听，底部固定条显示名称、实际状态、当前/总时长、暂停/继续和关闭；列表试听SVG与媒体play/pause/error/ended事件同步。换曲先停止旧源，pagehide/页面隐藏时释放。S/O/V可试听，不与H5音量、选曲、会话共享存储。早期Chrome/转码AAC夹具证明play/currentTime、单实例及离页停止；后续正式后台另完成获准OSS曲目试听及启用。弹窗聚焦、隐藏控件与小屏可达性仍按各自实际浏览器证据限定，不能扩大为手机验收。

STEP-020补充：后台原生试听成功不能单独证明前台跨域音频图可用；实际上传处理的CORS/Range门槛见API契约。上传状态对`storage_configuration`、`remote_cors`、`remote_range`、`remote_mime`分别展示配置、跨域播放、进度读取和响应类型失败，不把它们显示为就绪或引导反复上传。

STEP-004增加`bgm-directory-admin.js`及统一操作dialog。S/O行内开关控制启用/隐藏，星标设默认，紧凑试听与更多菜单承载其余动作；开关不在服务器确认前乐观切换。不合格资源的启用按钮禁用，服务端仍独立拒绝。启用经过“已试听，确认启用”明确人工动作。隐藏默认时必须选择替代曲；最后一首隐藏提示清空歌单。行内上下箭头每次先从GET/order读取完整成员并核对当前目录版本，再提交整份排列；保留“调整完整歌单”弹窗统一保存入口；不以分页列表冒充全量歌单。

目录操作先保存独立Admin localStorage凭据`lxm_admin_bgm_directory_operation`（仅一个未核对操作），再提交；失败保存时不请求。504/超时/权限中断保留id和原快照；刷新后可查询同id，未查到可显式原id原内容重发。明确409版本冲突提示未保存并刷新，必须重新选择；不会静默重基于新版本。请求采用既有returnErrorResponse选项，最长等待30秒，结果未知仍不重造操作。只在明确成功后刷新列表，不做乐观发布。

前端验证类型/5MiB/4096px/解码预览；服务器仍负责真格式、静态帧和完整解码。保存前在独立Admin localStorage键lxm_admin_bgm_cover_operation存UUID/快照/摘要，不保存文件。响应未知保留原id；刷新查询，未接收文件时重选同一文件继续原提交；原图与成功音频不被未确认选择覆盖。明确失败后提示音频无需重传；版本冲突保留候选但禁用保存，须手动“刷新已保存信息”核对最新版本后再提交。移除需点击选择及确认保存，结果区分关联已移除和旧文件待清理。
